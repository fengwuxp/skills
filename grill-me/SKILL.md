# Grill Me

## 定位

在实施前沿决策树逐一关闭关键分叉，直到用户与 Agent 达到 shared understanding。保留原始核心：一次只问一个问题、每问给推荐答案、Facts 先查、Decisions 才问、未确认前不执行。

本 Skill 是可独立调用的盘问能力，不是知止者内部 reference、产品或架构 Owner，也不授予执行权限。`wise-agent` 可在跨阶段任务中按需装载它；单一方案压力测试可直接使用本 Skill。

## 开始前

先确定盘问对象、当前交付、完成标准、设计分辨率、相关 Owner、最坏失败和允许读取的材料。设计分辨率按任务声明为方向、骨架、场景、动作、机制、实现或同等项目层级；它不是固定枚举，只用于判断什么现在必须关闭、什么应延期。优先恢复已有问题台账、决策快照、Issue、项目执行规范、Spec、ADR、PRD、源码、测试、日志、项目约规和知识库；不能只依赖当前聊天最后几轮。

需要自动判断“该自答还是该问”、进入多轮、跨上下文、存在历史结论、提到红线，或需要判断问题保真度、交接决策包时，读取 `references/question-ledger.md`；审查来源、版本或演进边界时读取 `references/source-map.md`。没有获准的持久载体时，在当前任务中维护台账并在退出前完整输出，不擅自创建目录或文件。

## 核心循环

1. **察实**：把当前 blocker 写成可核验命题，区分意图与约束、当前实现、历史决策、风险与红线，再实际读取匹配的文档、代码、项目决策、知识库、测试、日志或工具证据。
2. **温故**：按决策主题检索问题台账和历史结论；已确认、已排除或语义重复的问题不得换个说法重问。
3. **正名**：找到当前最影响方向、范围、公共契约、验收或风险的一个尚未关闭主 blocker。
4. **定层**：先判断该 blocker 是否会改变当前交付，或是否是达到当前设计分辨率的必要前提。更细、可批量统一设计或当前不阻塞的内容保留 `最终结论：pending`，另记 `queue_state: deferred` 与 `deferred_until`，从活跃队列移出并停止下钻；不得为追求完整把场景骨架连续拆到招式、参数或逐字表达。Owner 明确说“稍后统一设计”且已确认事实足以完成当前交付时，直接更新原问题为 `pending + deferred` 并知止，不得在同一延期簇中另造一个更高层问题继续追问。
5. **定媒**：只对温故、正名、定层后仍活跃的 blocker 判断问题保真度。文档、代码、测试、日志或受控调研足以裁决的低保真问题直接继续；视觉、交互、使用感、现场效果或真实性能等高保真问题先交给最小可观察物，例如原型、真实页面、可执行样例、基准或回放。交接只补证据，不替 Owner 裁决；证据返回后回到原问题台账。
6. **决断**：执行证据裁决，选择 `fact-confirmed`、`decision-reused`、`self-decided` 或 `ask-owner` 裁决动作，并映射到唯一的最终结论状态；前三类直接形成结论，只有证据无法关闭、当前仍活跃且影响 Owner 责任边界的剩余 Decision 才进入问询。
7. **一问**：仅对 `ask-owner` 一次问一个主问题，并给出推荐答案、已查证据、仍不能自决的原因、影响和本轮停止点；等待反馈后才继续。
8. **留痕**：每次裁决和实际问题都写入问题台账，记录问题 ID、决策主题、已查证据、裁决动作、推荐答案、用户回答、最终结论和下一阶段输入。组合、部分采纳或方向性回答必须分开记录行动意图与结果；用户确认 `A + 部分 B` 时，按 A 的主目标和 B 被明确采用的有限部分直接收口当前意图，不把“部分”自动当成含混而复问。用户确认“尝试、部分 B、争取”等意图，不等于确认命中、成功或后果；结果保持 pending。无论完整台账还是压缩输出，每条记录都必须原样保留 `裁决动作：<action>` 与 `最终结论：<state>`，不得只写其中一个或改成含混的“裁决 / 状态”。
9. **分层留存**：每轮问答后，凡是省略就会改变后续场景、段落、页面、流程、状态、验收、风险或责任交接的细节，逐项写入 `过程资产索引`；至少标明资产类型、状态、来源、适用范围、正典效力、`queue_state` 和下游消费者。过程资产可以是已确认细节、候选、观察、理由、依赖、后果、排除项或未知，不等于最终决策；快照中的过程资产仅交接，不构成正典，也不得自动进入生产或执行授权。
10. **写回检查点**：盘问进行中优先更新同一问题记录和相关过程资产。到达用户授权的写回检查点后，先写唯一领域权威；派生摘要在场景、主题或阶段检查点统一同步，不因每个微小回答反复扇出。项目规则要求即时写回时服从更具体规则，但仍只改必要权威和引用。
11. **知止**：当前交付达到约定设计分辨率，且剩余项均已关闭或以 `pending + deferred` 标明复审触发条件后，输出决策快照并停止扩问；没有其他已知 active blocker 时必须明确写“当前无 active blocker”，不得为继续对话制造问题。除最终选择和待决项外，同时输出相关过程资产及其效力边界，并请求用户确认 shared understanding。未确认前不执行方案。

遇到“这些细节到时候统一设计 / 先不要下钻”时，直接输出 `已确认上层选择 -> 延期项 -> 最终结论 pending -> queue_state deferred -> deferred_until -> 当前无 active blocker或仍有的唯一 blocker`；不为延期项另造“必要接口”“因果桥”或“最小约束”问题。遇到 `A + 部分 B` 时，直接输出 `A 为主目标 -> B 的明确有限动作 -> 行动意图 confirmed -> 结果 pending`；不把 B 扩成完整方案，也不把“试图”写成已发生效果。遇到延期项已满足触发条件时，直接沿原问题恢复 `pending + active`，只复述台账已有事实和过程资产；题面没有提供的场景、人物、证据或因果不得补写。

## `ask-owner` 输出

`fact-confirmed`、`decision-reused` 和 `self-decided` 只在台账留痕并继续裁决下一个 blocker，不逐条请求用户确认。只有 `ask-owner` 对外提出：

```text
问题 ID / 决策主题：
当前交付 / 设计分辨率：
待裁决命题 / 命题类型：
已查事实与历史结论：
裁决动作：ask-owner
最终结论：pending；证据冲突时为 conflict
证据冲突 / 置信边界：
本轮问题：
推荐答案：
依据与影响：
本轮停止点：
请确认：接受建议 / 修改答案 / 补材料 / 停止
```

用户说“按你建议推进”只关闭当前问题，不自动确认尚未展示的分叉，也不构成代码、Git、发布或生产授权。

## 历史与冲突

- 提问前必须检查语义重复，不以句子是否相同判断；同一对象、取舍和作用范围属于同一决策主题。
- 只有证据变化、历史结论互相冲突、风险升级或 Owner 明确要求重开时才能复问，并记录重开原因。
- 新证据与旧结论冲突时，不静默覆盖；把两者并列记录为 conflict，停止相关执行并只问一个裁决问题。
- 出现“红线、底线、不能碰、不可、禁止、不得、必须”等表达时，写入 red_lines；后续问题、摘要和执行前对账都必须显式检查。
- `queue_state: deferred` 不是拒绝、确认或新结论状态；只有达到 `deferred_until`、证据或风险变化、上游交付需要时，才回到同一问题记录并改为 active。Owner 只说“继续”或“恢复”不等于触发条件满足；若要提前恢复，须明确修改或豁免原 `deferred_until` 并接受对当前交付的影响。

## 经世校准

默认以察实、正名、审时、权衡、行验、知止约束盘问：先读事实，区分名实，判断变化和不可逆风险，再决定自答、询问或停止。只有用户明确要求经典视角，或时势、名实、止损问题确实需要独立校准时，才按需装载 `huaxia-practical-wisdom`；不得复制其框架或用古语替代证据。

## 退出与交接

退出时按 `references/question-ledger.md` 形成决策快照：当前交付与设计分辨率、已确认选择、被排除方案、active / deferred 待确认项、red_lines、相关过程资产、下一阶段输入、写回位置。过程资产只用于上下文恢复、复核和交接，不替代领域权威、最终结论、执行授权或生产准出。跨阶段任务交回 `wise-agent` 做执行前对账；独立盘问则直接交给用户确认。

## 红线

1. 不把可查 Facts 变成对用户的提问，不为表现深入无限延长访谈。
2. 不把资料名称当作已核验，不把知识库或当前代码天然视为业务真相，不用模型记忆代替项目证据。
3. 不重复已确认或已排除的问题，不把上下文遗忘当作重问理由。
4. 不替 Owner 决定新的价值取舍、公共契约、高风险事项或红线冲突。
5. 不把自决、推荐答案或 shared understanding 写成执行授权、测试通过、CR 结论或上线批准。
6. 不记录密钥、客户隐私、未脱敏生产数据或无关个人偏好；持久化仍需遵守项目规则和用户授权。
7. 高保真问题未取得可观察证据前，不凭语言、模型记忆或偏好断言结论；同一 Owner 的同一决策主题不得并行盘问。
8. 不把行动意图写成已发生结果，不把 `pending + deferred` 当作下一轮自动续问，也不在每个微小回答后同步全部派生文档。
