# 问题台账与决策快照

## 使用时机

当 `grill-me` 进入多轮盘问、需要复用历史结论、可能跨上下文恢复、出现红线或需要形成下一阶段输入时读取。

## 不适用场景

- 一个问题即可关闭且不需要跨轮恢复的轻量确认。
- 只有可查 Facts、没有未决方案或设计分叉的任务。
- 已确认计划的执行与验证；此时直接交给对应执行能力。

## 读取后必须产出

- 每个问题、裁决动作及最终结论的可追溯记录。
- 已确认、已排除、待确认、冲突和 red_lines 的当前集合。
- 会改变后续产物或交接的过程资产索引，以及每项资产的状态和效力边界。
- 去重或重开依据，以及供下一阶段消费的决策快照。

## 需要继续读取的 reference

- 跨阶段执行前对账读 `wise-agent/references/delivery-execution-control.md`，仅在项目仓库上下文可用时读取。
- 需要经典决策校准时装载 `huaxia-practical-wisdom`，不在本文件复制经典框架。

## 按任务读取索引

| 任务 | 优先读取 | 跳过 |
| --- | --- | --- |
| 每轮记录问题与结论 | `问题记录`、`历史恢复与语义去重` | 不新建语义重复问题 |
| 从既有材料自行决定是否提问 | `证据先行的问询裁决`、`历史恢复与语义去重`、`自决边界` | 不把资料名称当作已核验 |
| 处理红线或结论冲突 | `红线`、`决策快照` | 不静默覆盖历史结论 |
| 跨阶段或跨上下文交接 | `台账载体`、`决策快照` | 不只依赖聊天记忆 |

## 台账载体

按已有权威载体就地更新：用户指定位置 -> Issue / 项目执行规范 / Spec / Decision Log -> 项目已有任务状态或知识库。没有获准载体时，在当前任务中维护并在退出前输出；不得为了台账自动创建 `CONTEXT.md`、ADR、知识库目录或新的任务系统。

## 证据先行的问询裁决

每次提问前必须完成以下裁决；目的不是多查资料，而是只问证据仍无法关闭的剩余 Decision。

1. 先写明当前交付和设计分辨率，再把 blocker 改写为“对象 + 待判断属性或取舍 + 作用范围或阶段”的待裁决命题；不改变当前交付、也不是达到该分辨率必要前提的细节不得进入活跃问题队列。
2. 标注命题类型并读取匹配的一手来源：
   - 意图与约束：用户当前明确结论、PRD / Spec、ADR、项目约规和可追溯知识库。
   - 当前实现：源码、配置、Schema、测试、日志和工具回读。
   - 历史决策：问题台账、Decision Log、Issue、项目执行规范、ADR 及其 Owner 状态；旧 Goal 只作历史来源。
   - 风险与红线：Owner 原意、权限边界、强制约规以及适用的安全、合规或生产证据。
3. 实际读取内容和锚点并交叉核验，不得只列资料名。意图证据与实现证据回答不同问题，不能互相覆盖；代码和测试只能证明当前行为，不能自动定义正确业务语义。
4. 知识库只有能回链来源、Owner、适用范围和更新时间时才能作为已确认依据，否则只作检索线索；聊天摘要、模型记忆和无锚点转述也只作线索。
5. 形成唯一裁决动作：
   - `fact-confirmed`：匹配证据足以确认事实，直接自答。
   - `decision-reused`：存在仍适用的 Owner 结论或项目规则，直接复用。
   - `self-decided`：低风险、可逆、在授权内且不触碰 red_lines，采用默认选择并写明回退与验证。
   - `ask-owner`：证据缺失、冲突或失效，或剩余项属于新的价值取舍、公共契约、高风险、不可逆和红线冲突；只问这一个剩余 Decision。
6. 按“裁决动作到最终结论的确定映射”写入唯一状态机：`fact-confirmed` -> `confirmed`；`decision-reused` -> 沿用原最终结论；`self-decided` -> `self-decided`；`ask-owner` -> `pending`，若因证据冲突触发则在 Owner 裁决前为 `conflict`。Owner 回答后只能更新为 `confirmed`、`rejected` 或继续 `pending`；`superseded` 只用于保留历史记录，必须指向替代问题或决策，不得再次询问原问题。`queue_state: active / deferred` 是独立的问询激活轴，不新增或替代最终结论。
7. 记录待裁决命题、命题类型、证据锚点、证据冲突、裁决动作和置信边界。前三类不得再问；`ask-owner` 必须说明已查什么、为何仍不能自决。历史恢复、语义去重和决策快照读取最终结论，并按决策主题读取相关过程资产；裁决动作只说明结论如何得到，不作为第二套状态。
8. 对外台账无论完整还是压缩，每条记录都必须原样包含 `裁决动作：<action>` 和 `最终结论：<state>`；不得省略任一字段，也不得用“裁决”“状态”等近义标签替代。

## 问题记录

```text
问题 ID：稳定编号，例如 Q-001。
决策主题：对象 + 取舍 + 作用范围或阶段，用于语义去重。
当前交付：本轮实际要形成、确认或交接的产物。
设计分辨率：方向 / 骨架 / 场景 / 动作 / 机制 / 实现或项目定义的同等层级。
待裁决命题 / 命题类型：本轮要关闭的判断，以及意图与约束 / 当前实现 / 历史决策 / 风险与红线。
父主题：当前设计树分支；没有则为空。
问题：本轮只保留一个主 blocker。
为何现在问：它将改变的方向、范围、契约、验收或风险。
已查证据：历史问答、文档、代码、测试、日志、规则、知识库及锚点。
证据冲突 / 置信边界：不一致、失效、缺口及当前结论不能覆盖的范围。
裁决动作：fact-confirmed / decision-reused / self-decided / ask-owner。
问题保真度 / 求证媒介：低保真或高保真；高保真时记录最小可观察物。
决策包 ID / 交接原因：需要交接时填写；没有则为空。
推荐答案：Agent 建议、依据、代价和反证。
用户回答：原意摘要；不伪造原话。
行动意图：用户确认要尝试、优先或组合采用的动作；没有则为空。
结果 / 后果：只有证据或用户明确确认时填写；未确认写 pending，不从行动意图推定。
最终结论：confirmed / rejected / pending / self-decided / conflict / superseded。
queue_state: active / deferred；只表示是否进入当前问询队列。
deferred_until：queue_state 为 deferred 时填写可观察的恢复条件，否则为空。
替代记录 / replacement：最终结论为 superseded 时填写替代问题或决策 ID，否则为空。
red_lines：本题命中的红线、底线、禁止或必须项。
影响范围：受影响的对象、文档、模块、任务或阶段。
下一阶段输入：可直接消费的约束、选择和待办。
重开原因：仅在证据变化、结论冲突、风险升级或 Owner 要求时填写。
写回位置 / 更新时间：真实载体和当前时间；未知则标待确认。
写回检查点：用户授权写回、当前交付检查点、领域权威变化或项目更具体规则。
过程资产索引：会改变后续产物、交接或复核的关键细节；逐项记录资产 ID、类型、内容/原意、来源锚点、状态/效力、适用范围/时点/视角、影响/下游消费者、升格或复审条件、写回/交接位置。
```

问题提出后立即建立记录；用户反馈后在同一记录更新最终结论，不另建一个语义重复问题。自决也必须建记录，不能只在回答里一带而过。

## 历史恢复与语义去重

提问前依次执行：

1. 恢复最近决策快照和未关闭问题，再读取关联 Issue、项目执行规范、Spec、ADR、PRD、代码、测试和知识库；旧 Goal 只用于追溯，不作为当前状态。
2. 用“对象 + 取舍 + 范围或阶段”生成决策主题；比较含义，不比较措辞。
3. 最终结论决定问题状态：命中 confirmed、rejected 或 self-decided 时复用结论，不再提问；命中 `pending + active` 时继续原问题，不新建编号；命中 `pending + deferred` 时只恢复其 `deferred_until`，条件未满足不得续问；普通的“继续、恢复、接着问”不改变该判断，Owner 若要提前恢复必须明确修改或豁免原触发条件及其影响。命中 conflict 时只问原冲突的裁决问题；命中 superseded 时保留原记录、沿 replacement 指针读取替代结论，不重新提问原问题。相关过程资产供恢复、复核和交接核对，但不改变最终结论或领域权威。
4. 发现语义重复但措辞不同，合并到原记录并标注 duplicate；不得重问。
5. 只有证据变化、历史冲突、风险升级或 Owner 明确要求时重开，保留旧结论并填写重开原因。

上下文不足以确认历史是否存在时，先读取允许的载体；仍无法恢复时说明缺口并请求用户提供位置，不假装这是一个全新问题。

## 自决边界

| 情况 | 动作 | 留痕 |
| --- | --- | --- |
| 可从文档、代码、测试、日志或工具确认的 Facts | 自答，不问用户 | 证据锚点与事实结论 |
| 已有 Owner 批准的决策或明确项目规则 | 复用，不重问 | 来源、适用范围和更新时间 |
| 低风险、可逆、在当前授权内且不触碰 red_lines | 可 self-decided | 默认选择、回退和验证条件 |
| 新价值取舍、公共契约、高风险、不可逆或红线冲突 | 一次问 Owner 一个 blocker | 推荐答案、影响和停止点 |
| 证据彼此冲突或来源失效 | 停止覆盖与执行 | conflict、冲突证据和裁决 Owner |

“自行决定”只减少不必要提问，不扩大写文件、Git、联网、发布、生产或不可逆权限。

## 设计分辨率、延期与写回

设计分辨率回答“本轮需要设计到哪一层才足以交付”，不按领域固定层数。活跃问题必须满足至少一项：会改变当前交付；是达到当前分辨率的必要前提；不处理会造成不可逆风险、公共契约冲突或无法验证。其余细节保留为过程资产或原问题中的 `pending + deferred`，并填写可观察的 `deferred_until`；延期不是拒绝，也不能在下一轮自动恢复。

Owner 明确要求某组细节稍后统一设计，且现有确认已经满足当前交付时，采用固定收口：保留现有确认；把该组未决项写成 `pending + deferred`；写明 `deferred_until`；停止该分支。不要为了继续 Grill 而把同组细节重新命名成“必要接口、因果桥、最小约束”再问一次。若该未决项实际是当前交付硬阻塞，则按本节硬阻塞规则冻结依赖交付，而不是另造问题。

用户给出组合、部分采纳或方向性答案时，采用固定收口：A 保持主目标；只吸收用户明确点出的 B 的有限部分；行动意图记为 confirmed；命中、成功及其他结果保持 pending。除非“部分 B”无法在不改变责任、公共契约或红线的情况下解释，否则不重新询问其授权边界。“尝试逼退、尝试迁移、尝试重试”不证明已经命中、迁移成功或重试安全。

写回检查点控制扩散：盘问中先更新同一问题记录和相关过程资产；到用户授权的写回、当前交付、领域权威变化或项目强制检查点时，先更新唯一权威，再批量同步必要派生摘要。不得因每个微小回答反复改写全部消费者；也不得以批量写回为由延迟项目明确要求的即时权威修复。

### 状态转换最小输出

以下是状态转换的用户可见最小形状，不要求复述全部内部台账字段：

```text
延期：已确认选择；延期项；最终结论 pending；queue_state deferred；
      deferred_until；当前无 active blocker时输出快照并停止。

组合答案：已确认的主目标；被采用的有限部分；行动意图 confirmed；
          结果 pending；下一项是 active 还是 deferred；不重问当前组合。

条件未满足：沿原问题保留 pending + deferred；列出未满足的 deferred_until；
            当前无 active blocker时输出快照并停止。

条件已满足：沿原问题改为 pending + active；恢复关联过程资产、已确认选择、
            排除项和 red_lines；只问一个会改变当前交付的 blocker。

当前硬阻塞：说明依赖交付被冻结；提出一个 active Owner blocker；
            只允许明确无依赖的工作继续，不给执行或发布授权。
```

写回检查点命中时，用户可见回答至少说明唯一权威现在写回什么、派生摘要延到哪个检查点；继续 Grill 前只需说明下一项的 active / deferred 结论，不展开内部同步过程。

三类常见回复必须优先使用固定形状：

```text
延期回复：确认上层选择；列延期项；最终结论 pending；queue_state deferred；
deferred_until；当前无 active blocker或列出唯一 active blocker。不得新增同簇问题。

组合回复：A 为主目标；B 只取用户明确有限动作；行动意图 confirmed；
结果 pending；继续前只判断下一个 active / deferred 项。不得扩展 B 或推定效果。

恢复回复：沿原问题编号；只回读原记录已有事实、资产、排除项和 red_lines；
queue_state 改 active；最终结论仍 pending；只问一个当前 blocker。不得补题面之外的场景事实。
```

## 名相与决策写回路由

当问题收口时，先正名再写回：判断得到的是什么，谁有权定义，应进哪个已有权威。Grill 只做分类、冲突暴露和交接，不成为通用领域模型 Owner。

| 类型 | 判断信号 | 最小落点 | 禁止结果 |
| --- | --- | --- | --- |
| 领域名相 | 业务上稳定、上下文特有、会被多份产物复用的概念名称 | 项目已有术语库、领域模型或其他领域权威；产品语义优先转下一行 | 不把通用技术词、功能名或暂时文案写成领域词汇 |
| 产品概念 | 会改变主体、对象、状态、规则、指标、责任或验收 | 当前 PRD、产品概念卡或 Concept Lifecycle Card，由 `product-architecture-expert` 持有语义 | 不用代码、数据库或页面反向裁决产品定义 |
| 工程决策 | 涉及架构形态、技术选型、公共契约或跨上下文关系 | 按 `senior-software-architect/references/adr-and-tradeoff.md` 的三条准入门槛形成 ADR candidate；本表只以难逆、无背景会意外、真实取舍作路由摘要，不替架构师裁决 | 不为可逆实现细节、显而易见的约束或无备选的事实制造 ADR |
| 过程细节 | 暂时、可逆、尚待原型 / 测试 / 运行反馈，且不改变领域语义 | 同一问题记录或 process-only 过程资产 | 不扇出到术语库、PRD、ADR 和全部派生摘要 |

每个 writeback candidate 至少保留：路由类型、规范名称或决策命题、定义与不等于、Owner、来源锚点、目标权威、适用范围 / 时点 / 版本、`candidate_status: pending / confirmed / rejected`、验证、失效或复审触发、写入授权状态。`candidate_status` 只表示 Grill 候选是否已收口，不代表目标权威已接受。

`target_status` 是可选字段，值域、转换和 Owner 由目标权威定义：产品概念沿用产品概念生命周期，ADR 沿用 `adr-and-tradeoff.md`，process-only 资产沿用过程资产状态。目标权威支持版本替代时才按其契约填 `supersedes / superseded_by / reconsiders`；不支持或本轮不适用时省略，不写空段伪装完整。没有写入授权时，候选只进决策快照和交接，不自动创建 `CONTEXT.md`、ADR 目录、第二术语库或平行台账。

本节只完成 Grill 阶段的候选预分类。跨阶段任务在执行前由 `wise-agent/references/delivery-execution-control.md` 复核 Owner、证据、授权和真实落点；专业语义仍由产品、架构或其它领域 Owner 裁决。

遇到时势或权威冲突时，把产品权威、ADR、当前代码 / 测试和口头结论分层记录为 `conflict`；代码只证明当前实现，不自动定义正确业务语义。未裁决前停止依赖该语义的执行；产品语义交产品 Owner，工程决策变更以新 ADR candidate 双向标记替代关系，不静默改写旧决策或复活已替代值。

经世镜片在本路由中只作校准：名实对应路由类型与责任，审时对应状态、版本和复审触发，权衡对应 ADR 门槛和反证，行验对应验证、失效与复盘。对外交付只写这些现实字段，不用经典名词替代事实、专业 Owner 或验收。

## 过程资产与领域载荷

过程资产解决“细节不能丢，但不应伪装成最终决策或第二正典”的问题。只有省略后会改变后续场景、段落、页面、流程、状态、验收、风险、责任或交接的细节才进入索引；纯措辞、一次性草稿和不影响后续的闲聊不进入。

每项过程资产至少保留：

```text
资产 ID：稳定编号，可被问题、决策包和交接引用。
类型：constraint / accepted-detail / candidate / observation / rationale /
      excluded / unknown / dependency / consequence / handoff。
内容 / 作者原意：只记录可复用的最小细节，不复制整段对话。
来源锚点：原话、文档标题、代码/测试/日志、观察物或版本。
状态：confirmed / candidate / pending / rejected / superseded。
正典效力：process-only / handoff-only / reference-only / writeback-eligible。
queue_state：active / deferred；只表示当前是否消费或询问。
deferred_until：延期资产或问题的恢复条件；未延期为空。
适用范围 / 时点 / 视角：适用阶段、场景、读者/用户、POV、版本或载体。
影响 / 下游消费者：省略会改变什么，交给哪份文档、章节、页面、流程或验证。
升格条件 / 复审条件：何时可进入领域权威，或什么变化会重新打开。
写回 / 交接位置：真实载体；未知时明确标待确认。
```

`过程资产`与`最终结论`分轴：最终结论决定是否重问以及决策状态，过程资产只提供上下文、理由、细节、限制和交接输入。`process-only`、`handoff-only`、`reference-only` 不得直接写入领域正典；`writeback-eligible` 也只表示具备进入权威的条件，不表示已经写回。专业 Skill 可在过程资产中挂 `domain_payload` 引用，例如 novelist 的 `T/P/EV/POV`、文档的文种效力与来源版本、产品的对象/规则/验收、UI 的状态矩阵和节点证据；Grill 不重定义这些领域字段。

决策快照除“已确认选择、被排除方案、待确认项、red_lines、下一阶段输入”外，增加“过程资产（仅交接，不构成正典）”。恢复时最终结论决定是否复问，同时按决策主题懒加载相关过程资产；相关过程资产供恢复/交接核对，但不改变最终结论或领域权威，避免重新发明细节或把候选误当事实。

## 保真度与媒介路由

每次媒介判断都在历史恢复、语义去重和主 blocker 确定之后进行；已经 `confirmed`、`rejected`、`self-decided` 或 `superseded` 的同一决策主题直接复用或跟随替代记录，不因属于高保真问题重新交接。

先判断关闭当前命题需要什么证据，而不是按问题字数、会话轮数或固定 token 阈值猜测。

| 问题保真度 | 可用证据 | 动作 |
| --- | --- | --- |
| 低保真 | 文档、代码、测试、日志、受控调研足以判定 | 沿用证据裁决与一次一问。 |
| 高保真 | 视觉密度、交互手感、真实使用路径、现场效果、真实性能等必须观察实物才能判断 | 先交给最小可观察媒介：原型、真实页面、可执行样例、基准、回放或受控试点；观察证据返回后回到原问题记录。 |

高保真交接不是第五种裁决动作，不改变 `fact-confirmed`、`decision-reused`、`self-decided`、`ask-owner` 的状态映射，也不替 Owner 做价值取舍。未取得观察证据前不得把它写成事实结论、shared understanding 或执行授权。

## 决策包与交接

当决策主题跨多个独立 Owner、范围或证据媒介，且一个包内无法继续保持一个主 blocker 时，拆成可独立关闭的决策包。每个决策包必须保留：

```text
决策包 ID：稳定编号，例如 DP-001。
当前交付 / 设计分辨率：本包服务的产物及关闭深度。
范围 / 排除项：本包只关闭什么，明确不处理什么。
Owner / 决策主题：谁对哪一个取舍负责。
输入快照：关联问题、已确认选择、被排除方案、待确认项和 red_lines。
证据媒介 / 交接原因：为什么必须阅读、观察、原型、基准或回放。
返回产物：需要返回的观察记录、样例、指标或结论证据。
写回位置：原问题台账、决策快照和下一阶段输入的真实位置。
预算 / 停止条件：当前任务的时间、上下文、验证成本和无进展边界。
```

决策包只承载证据收集与收敛，不是执行授权。返回后必须以原决策快照对账，已确认选择、被排除方案、待确认项和 red_lines 仍然有效。

只有决策主题、Owner、输入、red_lines 和写回位置均不重叠的决策包，才可交给 Worker 并行；同一 Owner 的同一决策主题不得并行，存在共享公共契约、顺序依赖或红线时也必须串行。

## 红线

命中“红线、底线、不能碰、不可、禁止、不得、必须”等表达时：

1. 原意摘要写入 red_lines，并标记来源与适用范围。
2. 后续问题先检查是否触碰；触碰时不得用默认答案绕过。
3. 新结论若可能削弱红线，必须重开原决策主题并交 Owner 裁决。
4. 决策快照和执行前对账必须逐项复述，未对账不得执行。

## 决策快照

```text
已确认选择：关联问题 ID 与证据。
被排除方案：关联问题 ID 与排除原因，不得复活。
待确认项：分别列 active 与 deferred；包含 Owner、停止影响和 deferred_until。
red_lines：不可静默弱化的约束及来源。
过程资产（仅交接，不构成正典）：资产 ID、类型、状态/效力、来源、适用范围、影响、下游消费者和升格/复审条件。
下一阶段输入：目标、范围、约束、验收、验证和允许动作。
写回检查点：下一次允许或必须同步领域权威与派生摘要的条件。
写回位置：Issue / 项目执行规范 / Spec / Decision Log / 任务状态 / 当前任务输出。
```

退出条件不是问题数量，而是当前交付达到约定设计分辨率，关键分叉均已 confirmed、rejected、self-decided、明确 `pending + active`，或以 `pending + deferred` 给出恢复条件，且用户确认 shared understanding。连续两轮没有新证据或新决策时停止扩问；Owner 要求稍后统一设计时立即停止该分支，不继续下钻。
