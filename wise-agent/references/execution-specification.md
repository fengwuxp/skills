# 项目执行规范

本文是知止者处理跨轮、长任务和大目标时的持久执行权威。用户说 `Goal`、`长期推进`、`按计划持续做` 或类似表达时，先把目标落入项目已有 `OpenSpec / Spec / Issue / 任务计划`；不创建或恢复运行时 Goal，不把会话、摘要或模型记忆作为状态源。

项目执行规范只固定模型不能自行决定的承重事实；切片内部保留方法自由。默认给出目标、约束、退出标准和验证，不把实施者能够依据当前代码与反馈自行决定的步骤写死。

## 使用时机

- 任务跨会话、跨阶段或跨多个可独立验收切片，需要可靠恢复。
- 用户提出 Goal、长任务、大目标、持续推进或按计划执行。
- 上下文压缩、模型 / Harness 变化、权威材料更新或多方会商可能造成认知偏移。
- 需要把成功标准、授权、当前切片、证据、停止和下一入口放入项目权威载体。

## 不适用场景

- 当前会话能够完成的一步、单文件或边界清楚任务，直接执行并验证。
- 路线仍模糊且无法形成可靠 Spec 时，先按 `planning-execution-admission.md` 关闭关键决策。
- 只想让 Agent 无限运行、自由扩范围或替人类作公共契约、高风险和不可逆决策。
- 以计划、状态、运行轮数、模型自述或 validator 通过冒充真实交付。

## 读取后必须产出

- 项目已有的唯一执行载体及其 revision；没有合适载体时只提出最小落点，不并建第二状态源。
- 当前目标、成功标准、非目标、授权、权威证据、当前切片、验证、停止条件和下一入口。
- 当前切片结论：`eligible / blocked / stale / verified`，以及支持该结论的一手证据。
- 本轮 delta：实际动作、产物锚点、验证结果、决策变化、残余风险和下一责任人。

## 需要继续读取的 reference

- 路线尚未清楚或存在关键产品分叉时读 `planning-execution-admission.md`。
- 单个切片需要反复执行、观察和验证时读 `delivery-execution-control.md`。
- 跨阶段生命周期和工程交接读 `delivery-lifecycle.md`、`engineering-governance.md`。
- 跨上下文恢复、多方权威对账读 `context-handoff.md`。
- CR、准出和发布证据读 `verification-review-release.md`。

## 1. 正名与迁移

- 目标是业务方向和完成线；执行规范是项目持久载体；当前切片是一次可独立验证的工作单元；Loop 只是切片内部的有界反馈循环。
- Goal 只作为输入别名或历史来源，不是运行模式、状态主键、授权、恢复前置或完成证据。
- 收到“创建 Goal”“恢复 Goal”“用 Goal 长期推进”时，转换为创建或更新项目执行规范；不得调用运行时 Goal 工具，也不得向用户再索要 Goal 模式选择。
- 旧 Goal ID 如需追溯，只能记为 `origin / provenance`，不能复制其中的当前状态、授权或执行依据。
- 正式 PRD、系分、ADR 继续各守领域事实；执行规范只保存计划、状态、证据指针和当前入口，不复制第二套产品或工程正文。

## 2. 最小执行规范

优先复用项目现有 `OpenSpec / Spec / Issue / 任务计划`。只有项目没有任何允许写入的载体且用户授权创建时，才建立一个最小任务文档。

```text
Execution ID / state_revision / status:
目标 / 成功标准 / 非目标:
Human Owner / execution steward / Checker:
authority_refs / revisions / fingerprints:
confirmed / excluded / pending / red_lines:
execution_basis:
current_slice / next_entry:
write_whitelist / read_only_scope / forbidden_scope:
authorization:
validation / evidence:
stop / stale / recovery_conditions:
residual_risk_owner:
```

字段应随风险裁剪；简单任务不得为了填表而跨轮化。`status` 可使用 `Draft / Ready / Active / Blocked / Verified / Closed / Superseded`，但状态必须由当前证据支撑，不能成为执行授权。

## 3. 切片准入与执行

1. 恢复时只回读项目执行规范、当前切片相关一手材料和当前工作区事实。
2. 一次只选择一个可独立验证的当前切片；真实无重叠并行收益成立时才投影 `work_graph`。
3. 切片先写清目标、约束、退出标准和验证，再判断 `eligible / blocked / stale`。
4. 只有写入授权、白名单、权威 revision、验证入口和停止条件 aligned 才执行。
5. 完成后由测试、回读、Checker 或 Owner 证据决定 `verified`；随后只回写 delta。
6. 下一切片必须重新准入，前一切片通过不自动扩展权限、范围或事实。

计划只负责让工作可恢复、可验和可停，不保证计划本身正确。公共契约、资金、权限、安全、数据迁移、发布和不可逆动作继续由对应专业 Owner 与授权门禁负责。

## 4. 模型自由度

- 对开放、可逆、存在多条正确路径的工作，只给目标、约束、退出标准和验证，让模型在切片内自行选择最短可验证路径。
- 对安全、资金、权限、数据损失、公共契约和不可逆动作，使用明确步骤、白名单、脚本或审批点；自由度随失败代价降低。
- 不按旧经验预写模型“应该怎样思考”，不因防漂移加载全部 Skills，也不把 A0-A9 等审计镜片机械展开成每轮表演。
- 模型可以调整实现方法，不能自行改目标、成功标准、权威事实、授权、当前切片、停止条件或准出标准。
- 连续发散没有新增差异、连续执行没有新增证据、验证不能缩小未知或出现范围漂移时停止。

## 5. 认知完整性

- `state_revision` 每次持久化递增；承重字段变化必须有 Owner、原因和证据支持的 `execution_transition`。
- confirmed、excluded、pending 保持互斥；`execution_basis` 只能引用 confirmed，换轨必须显式迁移。
- authority revision、fingerprint、有效期或复核条件变化时，依赖结论先标 stale；旧摘要不能自动恢复 Ready / Active / Verified。
- 每个切片开始 just-in-time 回读承重字段和相关一手来源，结束只写 delta；不把整段对话、推理轨迹或完整旧材料反复塞回上下文。
- 需要确定性审计时投影 JSON 并运行 `scripts/check_state_contract.py --previous`；`current_slice`、`next_action` 或 `authorization` 跨版变化也必须进入 `execution_transition`。投影只证明声明结构和迁移一致，validator 绿灯不构成切片准入或授权证据，Checker 仍须回读权威来源。

## 6. 消融与回补

模型、Harness、工具集或主要上下文策略变化后，先在隔离环境做消融：以同一 runner / model、相同任务与验证比较最小上下文基线和当前候选。安全、权限、数据保护、业务不变量和真实验证门禁不得作为普通提示词删除。

- 删除不能回链重复失败、明确风险或项目事实的提示、Skill 路由和脚手架候选。
- 实际运行真实任务，观察失败位置和验证结果；静态 fixture 只证明契约存在。
- 只有模型反复在同一边界失败，并且能形成失败样例、最小修复和回归证据时，才把规则加回来。
- 评测被做满、任务分布变化或无法区分候选时，更新评测；不保留只会制造绿灯的检查。
- 不从外部文章或单次成功推导固定半年周期、模型普遍能力或无限自治结论。

## 7. 经世镜片

华夏经世智慧只校准取舍，不另造流程：

- **察实**：先读项目、源码、测试和当前 revision，不从目标名称或模型摘要推断现实。
- **正名**：目标不是 Goal 工具，执行规范不是授权，计划通过不是交付完成。
- **审时**：探索期可宽，执行期收敛，模型 / Harness 变化后旧规则先复核再继承。
- **行验**：以最小可逆切片取得真实反馈，先有验证能力再扩大任务难度。
- **知止**：路线清楚不再扩流程；规则无重复失败证据不添加；证据、授权或恢复条件不齐立即停止。

## 8. 迁移与停止

- 现有 Goal Ledger 若仍被项目使用，先迁移或映射到项目已有 OpenSpec / Spec / Issue / 任务计划；保留历史引用，不复制新旧两份当前状态，也不因改名覆盖项目既有语义。
- runtime Goal 仅可作为历史 provenance；不得恢复、续期、自动关闭或作为下一切片准入条件。
- 迁移先改权威入口与验证，再改用户指南和历史 fixture；不得通过全文改名掩盖旧自治语义仍然存在。
- 命中权威冲突、旧状态复活、无 Owner 的执行依据变化、缺验证入口或用户授权变化时停止并交还责任人。
