# 创见探索与求真验证

## 使用时机

- 输入是原创设想、非标方案、产品创新、架构突破或尚未形成主流表达的假设。
- 创新保护与事实验证可能互相抢位，需要先保留原始意图，再判断是否进入产品或工程交付。
- 需要把争论收敛为可证伪问题、最小可逆实验和人类 Owner 裁决点。

## 不适用场景

- 已确认的产品上下文、Spec 或代码任务只需要实现、测试或 CR 时，不回到创见探索。
- 本文不替代产品 Owner 的价值判断、专业领域判断、源码事实、测试、独立 Checker 或发布审批。

## 读取后必须产出

- 原始意图、原始观察和核心命题，不让 AI 的润色、类比或引用覆盖源头。
- 当前阶段（探索、决策或交付）、挑战的默认前提、最强版本、替代解释、反例和关键未知。
- 最小可逆实验 / 可证伪问题、反馈源、失败成本、停止条件和人类 Owner 裁决点。
- 只有被真实证据支持的结论，才允许进入产品上下文、Spec、Skill 或长期知识。

## 需要继续读取的 reference

- 需要现实取舍校准时读取 `huaxia-practical-wisdom/references/classical-lenses.md`、`decision-practice.md` 和 `evidence-boundaries.md`。
- 形成产品上下文或工程交接时再回到 `product-to-engineering-lifecycle.md`。
- 进入代码、测试、CR 或发布时回到 `senior-software-architect` 与 `verification-review-release.md`。

## 按任务读取索引

| 任务 | 优先读取 | 跳过 |
| --- | --- | --- |
| 保护原创意图 | `Round 0G` 的正名、审时、权衡 | 不用主流程度或模型流畅度否决 |
| 验证突破性假设 | `Round 0G` 的行验、化 | 不把新颖或反共识直接当成正确 |
| 进入产品 / 工程交接 | 本文输出卡，再回读目标阶段 reference | 不把探索卡当 Execution Grant |

## Round 0G：创见保护与求真分轨门禁

当输入尚未形成主流表达时，先护其意，后校其理。文章观点只能作为风险假设，不能替代当前事实、Owner 判断或工程验证。

- **正名**：记录原始意图、原始观察和核心命题；不让 AI 改写覆盖源头。
- **审时**：区分探索期、决策期和交付期。探索期允许假设，决策期要求价值与责任明确，交付期才进入可执行契约与工程证据。
- **权衡**：不把主流共识、文献数量或模型置信表达当成真理；不把新颖当成正确，也不把反共识或模型生成直接当成正确。
- **行验**：把争论压缩成最小可逆实验、反例检查或可证伪问题，明确反馈源、失败成本和停止条件。
- **化**：经人类 Owner 选择且被真实证据支持的结论，才进入产品上下文、Spec、Skill 或长期知识；一次性观点留在任务材料中。

最小输出卡：

```text
原始意图 / 原始观察：
可能挑战的默认前提：
最强版本与替代解释：
反例 / 边界：
关键未知：
最小可逆实验 / 可证伪问题：
人类 Owner 需要裁决：
不得提前做的工程动作：
```

求真验证回到一手材料、来源、测试、可观察结果和独立复核；缺少证据时标记为待确认或停止。创见探索与求真验证是阶段路由，不是对外新增模式、人格、Owner 或执行授权。
