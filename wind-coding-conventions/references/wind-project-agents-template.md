# Wind 项目 AGENTS.md 专项模板

## 使用时机

用户要求初始化或改进 Java 项目约规，且项目声明、依赖、包名、类型或模块上下文已经证明适用 Wind 时读取。本文只提供项目事实和 Java/Wind 差量，可独立形成项目规则，也可合并到已有工程基线；不再复制全局行动规则、通用规划框架和能力菜单。

## 不适用场景

普通 Java 项目从通用 Java 约规提取差量，不采用本文的 face/impl 或 Wind 类型规则。项目现行规则和有效契约优先；附近代码用于核对事实，不能覆盖已确认规范。用户没有要求改项目规则时，不因一次编码或 CR 重写 `AGENTS.md`。

## 读取后必须产出

- 初始化时从实际项目定位模块、JDK、构建与 CI、消费者、相关测试及格式配置；可查事实自行填写。只把影响执行的未知项标为待确认，不虚构可运行命令或把所有占位项交给用户填写。
- 改进时直接在授权范围内做最小 patch：保留有效项目特例，移除与当前权威重复或冲突的旧副本；缺少影响契约或权限的决策时，只暂停相关动作。
- 通用工程原则由项目的有效工程基线维护；需要初始化语言无关的工程约定时交 `senior-software-architect`。本专项独立使用不要求另装架构师或知止者，也不因此缺失必要的 Wind 规则；实际源码任务仍按其工程能力与规则依赖执行。
- 生成后核对命令、路径、模块、规则适用信号和安装可达性。模板没有授予安装、Git、部署、生产、迁移或删除权限。

## 需要继续读取的 reference

Java、Wind 与代码样式细则分别读取本包的 `java-coding-conventions.md`、`wind-coding-conventions.md` 和 `code-style.md`；只展开当前项目实际适用章节。

## 模板正文

生成时替换有证据的项目项，删除不适用章节；下面的占位符不应原样作为可执行项目配置交付。

```markdown
# AGENTS.md

## 项目事实

本项目遵循 Wind 编码约规。

- 核心能力与使用者：<一句话说明>。
- 入口与模块：<实际路径、职责和允许依赖方向>。
- 兼容与数据特例：<当前消费者、历史数据约束及有依据的例外；没有则省略>。

## 适用规则

- 先读本项目根目录与局部规则、当前任务相关源码、调用方和测试，再从运行时能力目录读取 `wind-coding-conventions` 的适用章节；Skill 名称不当作消费项目内的文件路径。
- 通用 Java、代码样式与 Wind 专项各按其权威 reference 执行，依赖专项依据实际版本和源码启用；不为套规则新增库。必要规则不可达时说明具体缺口，只暂停依赖它的写入。
- Java/Wind 约规由 `wind-coding-conventions` 提供；源码设计、实现、测试和 CR 由 `senior-software-architect` 承担；有 DDL/schema 等结构化输入的 Service 脚手架才使用 `java-service-code-generator`。具体调度按当前 Agent 与消费项目已有规则执行，不要求创建规划文档。

## 模块与源码边界

- face 承载稳定契约，impl 封装其实现与存储；真实模块不同则按本项目职责映射。对外契约不泄露 Entity、Mapper、Repository、MyBatis Page 或 QueryWrapper。
- 有稳定接口时，调用方依赖接口并通过组合使用能力；不为形式分层新增无职责的透传方法、浅服务或 Mapper 包装，不以生产路径中的内存版业务 Service、Fake/Mock 或模拟入口冒充完整能力。
- 新增或调整接口、模型与方法先核对真实消费者、责任、业务不变量和可验证结果；项目特例只记录本项目差异，不复制完整 Java/Wind 手册。
- 新增生产 Java 命名类型按 Wind 类型头 Javadoc 规则保留真实职责、可核验的 `@author` 和 `@since`；注释必要性及继承例外回到通用 Java 约规，不重复接口已说明的文档。
- 空值责任按不可信输入、持久化约束和 Java 空安全契约归位。已证明非空不层层判空，数据库约束不代替输入校验；Bean Validation 的服务边界直接读取 Wind 规则，不在此复制注解组合。
- Spring Bean 注册、依赖注入与 Lombok 日志注解按通用 Java 的实际依赖规则执行，无 Lombok 不为套规则安装。

## 日志与测试

- 关键业务状态变化和失败恢复应可追溯；记录必要的业务 ID、动作、结果和原因。使用项目已有 MDC 上下文，不在每条日志重复已注入的 traceId 等字段；异步缺失上下文时修复传播和清理。
- 不打印完整 Request/Response、Entity、SQL 或密钥、token、证件、银行卡等敏感内容。业务事件与可回放消息按稳定 `eventKey + params` 表达，不用可变文案作判断依据。
- 测试覆盖公开行为、状态、持久化事实、异常与必要的幂等/并发边界；不以私有方法、内部调用次数或实现步骤代替结果断言。fake/mock 用于合适的测试边界，不作为生产交付。

## 本项目验证入口

- JDK 与运行环境：<实际版本和需要使用的项目环境>。
- 构建/编译：<实际工作目录和命令>。
- 目标测试：<行为范围与命令>。
- 格式/静态检查：<实际采用的配置与命令>。

样式默认优先核对项目实际选用的 IDEA Code Style；已有明确的 formatter/CI 权威时遵从它。细则读取 `wind-coding-conventions` 的 `references/code-style.md`，缺少可确认样式时说明需要配置，不用个人默认设置或样本行宽填空，也不格式化无关代码。

代码、测试或构建变更按相关范围验证；纯文档修改只做适用检查。区分实际运行、失败与跳过项，说明原因和证据边界；验收后直接交付结果与尚未解决的问题，不强制输出固定字段或多余的下一 Owner。
```

## 维护边界

本文维护 Wind 项目差量与生成方式，细则仍分别归 `java-coding-conventions.md`、`wind-coding-conventions.md` 和 `code-style.md`。已有项目只补缺口，不把模板整体覆盖为新权威；局部例外须有事实与适用范围，不保存个人偏好、临时讨论、AI 推理轨迹或未验证结论。不把任何样本项目的包名、业务模块或命令照搬到新项目。
