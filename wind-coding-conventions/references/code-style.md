# 跨语言代码样式

## 适用范围

Java、TypeScript、JavaScript 及其他语言的新增、修改、生成、测试代码和格式 CR 均适用；只做业务或架构分析而不涉及源码排版时不读取。本文是可单独消费的样式规则，不要求非 Java 任务加载 Java / Wind 专项；语言语义与框架规则仍归对应专业能力。

## 样式来源与缺口

- 默认优先采用项目实际选用的 IntelliJ IDEA Code Style，分别核对目标语言和模块的设置。检查 `.idea/codeStyles/`、scheme 选择及其引用；目录存在、机器上有 `Default.xml` 或某个样本看起来一致，都不能证明项目采用了它。用户明确指定的 scheme / 导出配置可作为本轮依据，并说明是否已共享到项目。
- IDEA 内置格式器按适用 `.editorconfig` 的已定义选项覆盖项目设置，其余选项回到当前 scheme；只有缩进配置不能证明换行、import 或其他选项已确定。Java 设置不自动成为 TypeScript / JavaScript 的标准，嵌套模块也不自动继承另一个模块的格式器配置。
- 先遵从用户和项目明确的格式权威。已有构建 / CI 明确采用 Spotless、Prettier、Biome、ESLint 格式规则或语言原生工具时，保留其执行契约，核对 IDEA 是否调用同一工具；缺 IDEA 对齐时说明需要配置 IDE，不能静默覆盖现有检查。IDEA Reformat 可能实际委托 Prettier；以生效工具、版本、配置及文件范围判断结果，不以按钮名称认定格式器。
- 找不到可确认的目标语言样式，或 scheme / 工具配置有未决冲突时，明确告知用户“需要配置或确认代码风格样式”，指出缺失的语言、scheme 或冲突项，建议在 IDEA `Editor → Code Style` 配置并共享项目 scheme；不默选个人 Default，不用模型习惯、固定行宽、通配符阈值或本轮样本数值填补缺口。不因这一缺口擅自安装格式器、改 IDE 全局设置或新建全仓配置。
- 仅暂停依赖未定风格的批量格式化、统一风格迁移及合规结论。独立的业务修复可按已知设置和邻近代码保守编辑，明确样式待确认；未配置与已配置但工具不可用分开说明，不把前者包装成“人工按 IDEA 验证通过”。同一未变缺口不反复问询。

## 按语言核对

| 语言 | 本轮相关设置与语义边界 |
| --- | --- |
| Java | import 顺序与分组、普通 / static 通配符阈值及包例外；行宽、参数和调用换行、链式调用、lambda、续行缩进、短表达式及保留换行。普通 Reformat 与 Optimize Imports 分别验证；不从其他语言复制导入规则。 |
| TypeScript / TSX | 分别核对 TypeScript 与 JSX 排版、缩进、引号、分号、尾逗号、参数 / 对象 / 类型表达式换行、import 分组与 `import type`；使用当前模块的实际格式器与 lint 规则。import 整理不得改变类型导入语义或副作用模块的执行顺序。 |
| JavaScript / JSX | 核对 JavaScript 与 JSX 的对应设置及模块作用域，不套 Java 行宽或通配符策略；保持自动分号插入、字符串 / 模板内容和副作用 import 的运行语义。 |
| 其他语言 | 确认该语言的 IDEA 支持和项目已有格式命令；项目采用语言原生格式器时按其契约执行，不把 Java / JS 排版习惯复制过去。 |

只检查当前变更涉及的选项，不将上表变成每轮必须填的配置清单。SQL、正则、快照和字符串内容不是可任意重排的普通代码，折行不能改变其内容或断言。

## 执行与验证

1. 使用已确认配置和本地可用工具，限定本次文件或必要代码范围。格式修复不自动包含 Rearrange、Code cleanup、升级依赖或全仓重排；工具不能按局部执行时，先核对会修改哪些文件。
2. 处理过度折行时核对当前语言的 `Keep when reformatting → Line breaks`。已启用保留换行时，普通 Reformat 可能保留旧折行；本轮确需去除时，用 `Do not keep line breaks` 等当前版本支持的局部选项，并回读结果，不修改全局偏好或用正则拼接代码。
3. 批量统一风格前，先在本轮范围选有代表性的入口、实现、模型 / 转换或测试样本，确认导入整理、短声明 / 调用、链式调用和续行缩进的实际效果；样本与数量按差异选择，不能把样本通过写成全范围完成，也不顺势扩到未授权模块。
4. 回读 diff，确认没有语义变更、无关重排或新旧格式器互相改写，再执行项目已有 format / lint 检查。涉及 import、字符串或可能影响行为的改动时，补对应编译、类型检查或测试；不新造一套验证框架。
5. 交付说明采用的语言样式、实际工具和范围、已执行检查及缺口。工具不可用时可按已确认配置人工检查，但注明未执行自动格式化；`git diff --check`、结构守卫、编译通过都不能证明已按 IDEA 排版。

来源及版本核验见本 Skill 的 `references/source-map.md` 中“IDEA 跨语言代码样式”；IDEA、插件或项目格式器升级，scheme、模块作用域或 CI 权威改变时重新核对。
