# 单块学习与复训契约

## 使用时机

当用户要系统学习、真正掌握或继续一个跨轮知识主题，需要把材料转成当前可完成的学习块、练习、主动回忆和后续复训时读取。

## 不适用场景

- 一句话可以回答的静态事实、普通解释、网页摘要、翻译或资料整理。
- 用户目标是直接完成代码、PRD、系分、设计稿或其它专业交付，而不是学习该能力。
- 热点发现、定期监控或新闻增量汇总；它们不是学习闭环。

## 读取后必须产出

- 当前学习块的目标、时长、来源锚点、主关系、最小练习和掌握证据。
- 一次一道且不附答案的主动回忆题。
- 用户作答后的通过证据或具体知识缺口，以及明确的续接动作。

## 需要继续读取的 reference

- 需要核对本文方法来源、研究边界和未吸收内容时读 `source-map.md`。
- 具体主题事实由当前领域的一手材料、官方来源、源码、测试或对应专业 Skill 裁决；本文不提供领域知识。

## 按任务读取索引

| 任务 | 优先读取 | 跳过 |

## 一、输入与分型

只确认会改变当前学习块的字段：

```text
topic: 学什么
goal: 学完当前阶段要能做什么
baseline: 已会什么、卡在哪里
timebox: 本次可用时间
materials: 已有材料及其来源状态
state_path: 已有进度路径，或明确不落盘
```

信息缺失时一次只问一个问题。若用户已经给出基础、时长和目标，不重复盘问。

按知识变化速度决定证据策略：

| 类型 | 判断 | 当前块的来源策略 |
| --- | --- | --- |
| `stable` | 原理、定义和核心关系长期稳定 | 权威教材、大学课程、经典例题与常见错解优先；来源较老不自动降权 |
| `fast` | 版本、价格、产品状态或近期研究结论容易变化 | 获得联网授权后回到当前官方发布、原始论文或可复核实现，并标明 as-of 日期 |
| `mixed` | 原理稳定，工具或实现持续变化 | 原理层按 `stable`，工具层按 `fast`，不让单篇 quickstart 包办全部事实 |

先使用用户提供材料、当前仓库、源码和测试。缺少必要证据时说明缺口；联网只补当前学习块需要的最小来源集合。

来源按职责选择，不靠链接数量制造可信度：

- **原理源**：解释主关系和适用边界。
- **实操源**：能支持当前最小练习真正运行或操作。
- **错解源**：揭示新手最容易混淆的位置或失败条件。

一个来源可以承担多个职责，但同源转述仍是一条证据。当前块不需要的角色可以明确跳过，不为凑齐三角强行搜索。

## 二、单块契约

每次只展开一个 20 至 45 分钟内可完成的概念块；用户时间更短时缩小任务，不压缩掉必要关系。

```text
当前位置：这块在主题中的作用
主关系：本块唯一需要建立的对象、动作或因果
来源锚点：材料、章节、页面、符号或测试
解释：按用户基础减少跳步，正式术语在直觉之后出现
动手：一个可在 timebox 内完成的最小任务和一个小变体
可观察结果：什么现象说明任务跑到了预期位置
常见错误：错误发生在哪一步，如何识别
回忆题：合上材料后回答，一次一道，不附答案
```

练习不能只是照抄示例。最小任务先暴露主关系，小变体再改变一个条件；无法运行时可以使用纸面演练，但必须有可检查的选择、过程或结果。

## 三、验收

当前块至少取得以下两类证据才可进入下一块：

1. **能解释**：不用照抄原文，说清主关系和边界。
2. **能独立完成**：在最小提示下完成练习或小变体。
3. **能识别错误**：把失败定位到具体步骤、条件或误解，而不是只说“结果不对”。

一次答对只证明当前检索成功，不证明长期保留。脚本运行成功只证明练习可运行，不证明用户理解。无法取得两类证据时，缩小当前块或记录缺口，不以继续生成内容掩盖失败。

## 四、复训与续接

已有进度时先读取到期项。到期项存在则：

1. 选一题，只显示问题和必要上下文，不显示答案。
2. 等待用户作答，再按原答案锚点核对。
3. 通过时记录实际表现；失败时把“哪里没说清、哪一步混淆”写成具体缺口。
4. 与用户的目标保留期、表现和日程一起确定下一日期；不把任一固定天数序列称为普适最优。
5. 本题处理后再决定继续下一到期题或新内容。

续接锚点只记录：当前块、已取得的掌握证据、未闭合缺口、下一题或下一块。没有跨轮需求时不创建状态文件。

## 五、表达介质门禁

只在以下任一情况成立时考虑图解或最小交互：

- 难点是多个对象的空间关系或责任流向。
- 状态随一次操作变化，读者需要看到前后差异。
- 调整一个量会改变结果，亲眼验证比追加段落更有效。

图解只承担当前一个主关系。类比层、真实机制和失效边界必须区分；正式术语在直觉之后出现。普通结论、来源、练习和进度仍使用 Markdown。文件产物必须先确认绝对路径，并按目标视口实际验证；生成成功不等于视觉或学习效果通过。

## 六、队列脚本

`scripts/review_queue.py` 是离线 JSON 队列工具，不联网、不创建自动化，只读写 `--file` 指定的状态文件。日期必须由调用者显式给出：

```bash
python3 scripts/review_queue.py add \
  --file /absolute/path/progress.json \
  --topic RAG \
  --question "准备阶段和提问阶段分别做什么？" \
  --gap "混淆了切块、建索引和每次检索发生的阶段" \
  --answer-ref "checkpoints/rag.md#stages" \
  --due 2026-09-04

python3 scripts/review_queue.py due \
  --file /absolute/path/progress.json \
  --on 2026-09-04

python3 scripts/review_queue.py grade \
  --file /absolute/path/progress.json \
  --id 1 \
  --result fail \
  --on 2026-09-04 \
  --next-due 2026-09-07 \
  --note "仍把建索引说成每次提问都会执行"
```

`add` 必须包含真实问题、具体缺口、答案锚点和日期。`grade` 必须显式提供结果和下一日期。脚本不根据一次作答自动宣布“已掌握”。

## 七、安全与停止

- 创建学习包、状态文件或图解前确认绝对路径；不写入仓库、记忆目录或全局配置作为默认行为。
- 联网、安装、Git、浏览器登录态、自动化和定时任务分别取得授权；Skill 调用不提供这些权限。
- 来源不可读、许可不明或事实冲突时，标出限制并停止依赖该结论的学习块。
- 高风险专业主题的练习不替代医疗、法律、财务、安全或生产 Owner 的确认。
- 用户时间用尽、主动停止或当前掌握证据不足时，留下一个续接点后结束，不靠追加内容制造进度感。

静态 fixture、结构校验和脚本单测只能证明契约与确定性行为；真实学习改善需要相同主题的 baseline/candidate 对比、独立评审及延迟复测。
