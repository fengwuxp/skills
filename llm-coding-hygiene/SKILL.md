# LLM 编码卫生

## 定位

本 Skill 是 `code quality and review` 专项能力，用于减少常见 LLM 编码错误：默选假设、无证扩展、重复造轮子、局部补丁、无关清理和以自述代替验证。它可以在编码前审计划、编码中约束范围、编码后审 diff，但不成为第二行动主体，也不成为工程 Owner。

实际新增、修改、重构或修复代码时默认隐式生效，作为静默协同护栏约束实现过程；显式专项审查时才单独输出编码卫生结论。

项目 `AGENTS.md`、源码、测试和项目编码约规优先。上游原则、来源与本仓库扩展边界只在需要追溯时读取 `references/source-map.md`。

## 工作流

### 1. 察疑

- 先读用户原话、项目规则、与当前目标直接相关的源码、测试和已有证据，再区分事实、推断、待确认和范围外不做。
- 先从现有材料自答；只有剩余分歧会改变实现时才提出 blocker，不默选一种解释。
- 若契约未定，停止依赖该假设的实现；截止时间、上级催促和“测试会过”不能代替契约。

### 2. 定简

- 依次检查仓库已有能力、标准库、平台原生能力和已安装依赖，停在第一个满足目标的方案。
- 没有第二种真实策略、变化轴、Owner 或量化证据时，不增加接口、工厂、provider、配置、缓存或依赖。
- Bug 先查共享函数、边界与兄弟调用方；语义相同时在共享边界做一次最小根因修复，契约不同时保留差异并说明证据。

### 3. 限界

- 每一行修改必须回指用户目标、验收标准、源码事实或失败测试。
- 用户要求“顺便清理”也不能证明相邻旧代码属于当前目标；不清理既有 import、格式、注释或死代码，只清理本次修改制造的 orphan。
- 最终回读 diff，移除本次改动带来的重复、残留和越界修改。

### 4. 验成

- 把命令式任务转成可验证目标，写清保持行为、改变行为、非目标和失败条件。
- 实现功能或修复 Bug 时，先建立能复现缺口的最小行为检查，再做最小实现并运行相关验证。
- 只报告实际执行的验证、结果和未覆盖风险；静态 fixture、Agent 自述、计划或局部测试不能冒充行为提升、完整 CR 或生产准出。

## 协作边界

- 知止者持有跨专业、跨阶段或跨轮任务的目标、状态、授权和最终交付；本 Skill 只返回编码卫生专项结论。
- `senior-software-architect` 持有工程实现、Bug 修复、TDD、源码 CR 和生产风险；本 Skill 只是静默协同护栏，不改变工程主能力，也不重复工程流程。
- 只读源码 CR、仅诊断且不写代码、纯项目编码规范检查和文档任务不自动触发；用户显式调用本 Skill 时除外。
- `wind-coding-conventions` 持有 Java / Wind 项目编码约规；本 Skill 不创设命名、分层、依赖或框架规范。
- `security-engineering-expert` 持有跨层安全要求、控制与残余风险；本 Skill 不作安全准出。
- Ponytail 只补最小正确实现和可删除复杂度专项检查，不替代契约、根因、TDD、安全或工程 Owner。
- Superpowers 只补 brainstorming、计划、TDD、调试、Review 和验证方法，不成为新的事实、授权或准出来源。
- fixture、validator、测试和独立人工评审提供证据；Maker 不以自己的检查自证完成。

## 输出契约

按任务只给必要内容：

```text
事实 / 待确认：
最小方案：
允许修改 / 范围外不做：
成功证据：
Owner / 停止条件：
```

简单一行修改不展开检查卡、流程图或风险矩阵，直接完成并给最小验证。专项审查必须指出具体计划或 diff 证据；无问题时明确说明未发现，并保留测试或证据边界。

## 红线

- 不得用简单优先删除安全、权限、持久化、幂等、审计、错误处理或必要测试。
- 不因经理、工期、测试通过或用户要求而猜公共契约、扩大写入范围或降低验证标准。
- 不把“未来可能需要”当成真实变化轴，不为单实现创建抽象。
- 不在共享根因明确时只给报错入口加局部 guard，也不为代码更少强行统一不同契约。
- 不把本 Skill 变成新流程、默认 Hook、外部依赖、Git 授权、发布审批或生产结论。
