# 产品架构专家技能树

本技能树用于通用产品架构能力评估、学习路径、方案审查和任务拆解。支付与资金能力使用 `payment-expert` 的技能树，不在本文重复维护。

## 使用时机

- 用户要求评估产品专家能力、拆解学习路径、做岗位能力画像或规划通用产品架构能力地图。

## 不适用场景

- 用户要求直接产出 PRD、产品方案或图形化交付时，优先读取对应执行 reference。
- 用户要求支付、资金、账本、清结算、对账、卡、VCC 或跨境能力评估时，使用 `payment-expert`。

## 需要继续读取的 reference

- 通用产品架构读 `product-architecture-methodology.md`。
- PRD 读 `product-design-and-prd.md` 和 `product-prd-template.md`。
- 图形化读 `diagram-output.md`。

## 1. 产品架构基础

- 产品定位：目标用户、业务目标、价值主张、范围、非目标和成功指标。
- 场景分析：用户、业务、运营、异常和跨系统协作场景。
- 能力地图：前台、后台、数据、风控、集成和运营能力。
- 业务对象：定义、字段口径、生命周期、状态、关系、权限和审计。
- 业务流程：主流程、逆向、异常、人工、跨系统和通知流程。
- 业务规则：权限、额度、计费、审批、通知、风控、留存、报表和版本。
- 验收设计：用户、业务、运营、数据、风险验收和技术交接条件。

## 2. 产品经理基础与 PRD

- 文档分型：BRD、MRD、PRD、产品方案、评审材料和复盘的读者与责任。
- 流程表达：流程图、泳道图、状态机、用户旅程、服务蓝图和产品架构图。
- 用户研究：把问卷、访谈、画像、反馈和工单转成问题、证据与验证假设。
- 需求管理：需求池、价值评估、优先级、评审、跟踪、复盘和关闭标准。
- PRD：用户故事、功能、交互、异常、权限、埋点、报表和验收标准。
- 文档治理：区分 PRD/MRD/BRD、主文档与附录，最终正文保留版本状态和过程记录链接，不混入讨论过程。
- 规则矩阵：对象、触发、判断、动作、优先级、版本、例外和验收样例。
- 运营与数据：查询、审核、复核、导出、权限、日志、指标和数据质量。
- 图形化表达：按问题选择能力地图、用户旅程、服务蓝图、流程图或状态机；AI 草案必须回到 PRD、规则、证据和验收校准。

## 3. 复杂业务建模

- 多角色协作、多状态流转、多规则版本、多系统集成、多数据口径和多风险边界。
- 从稳定业务职责、对象不变量和真实变化轴划分产品能力，再由业务流程组合。
- 功能分配：把对象对外可见、有价值的交互行为追溯到目标或父能力，再分配到对象、流程、规则、数据和验收。
- 交付物必须回到主体、对象、流程、规则、状态、权限、数据和验收，不停在页面清单。

## 4. 产品治理

- 权限与审计：角色、资源、动作、数据范围、职责分离、日志和证据导出。
- 风险与兼容：人工审核、告警升级、字段演进、历史数据、灰度和回滚。
- 数据与上线：指标字典、血缘、质量、留存、验收矩阵、SOP、监控和复盘。
- AI 产品工作流成熟度：不把工具熟练度当成熟度，区分工具提效和 AI-shaped 工作重构，评估业务优势、流程、上下文、责任、验证周期、决策质量和返工率。

## 5. 可扩展垂直领域

- SaaS 订阅计费、交易市场、会员权益、供应链履约、数据产品和 AI 产品工作流。
- 新垂直能力先证明稳定职责、真实变化轴、独立输入输出和验证方式；支付与资金已独立为 `payment-expert`。

## 能力分级

- `L1`：识别用户、主体、目标、流程和基础对象，输出简单 PRD。
- `L2`：设计能力地图、对象、流程、状态机、规则和验收。
- `L3`：处理多角色、多状态、多规则、多系统协作并形成可交付方案。
- `L4`：建立风险、权限、审计、数据和上线治理。
- `L5`：跨业务域规划稳定能力、变化边界和长期治理体系。
