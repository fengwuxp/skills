# 审核任务中心 PRD

文档强度：标准。

## 阅读摘要

当前结论：统一审核入口。产品定义 / 产品视图：为运营提供可追踪的审核能力。主链路为提交、审核、通知；申请单由平台管理。

## 一、背景与问题

背景：审核积压影响运营；问题：人工路径不清，现状缺少统一入口。

## 二、目标与非目标

目标：提升审核效率并改善体验；非目标：不改结算规则；成功指标为处理效率和退回率可观察。

## 三、定性与范围

产品定性：存量审核流程治理；总体判断：先统一口径；范围是后台审核，不做范围是交易处理。

## 四、概要设计

概要设计：核心方案是统一审核入口和能力布局。核心对象为审核申请，归属主体为平台。

## 五、详细设计

详细设计围绕审核申请对象展开，状态从待审进入通过或驳回，生命周期在形成唯一结论后关闭，不变量是终态不得被重复裁决覆盖。

### SCN-001 运营审核申请

- 业务问题与期望结果：审核员需要完成判断，申请单形成可追踪结论。
- 参与者与责任：审核员处理，平台持有申请事实。
- 触发与前置事实：申请已提交且状态为待审。
- 主路径与状态变化：申请单由待审变为通过或驳回。
- 适用规则：R-001 适用于审核裁决步骤。
- 完成证据与验收种子：审核结论、操作者和时间可查询。
- 逆向、异常与停止：材料不足时驳回补充，外部来源不可用时停止裁决。

### 产品需求陈述

- 需求名称：保存唯一审核结论。
- 需求类型：功能。
- 责任主体：审核平台。
- 场景 / 前置状态：SCN-001，申请处于待审状态。
- 规范强度：必须。
- 要求的行为或业务结果：平台必须保存唯一的当前审核结论。
- 度量、时限或边界：重复裁决不得改变终态。
- 来源与可靠性：运营审核规则，已确认。
- 关联规则：R-001。
- 验收样例：重复提交裁决时返回原终态。

## 六、关键流程

主流程为提交、审核、通知；异常流程处理重复提交；人工处理支持补录。

## 七、业务规则与接口抽象

- 规则编号：R-001。
- 规则名称：待审申请裁决。
- 规则性质：场景裁决规则。
- 业务动机：防止终态被重复操作覆盖。
- 适用场景 / 步骤：SCN-001 / 审核裁决。
- 适用对象与范围：待审申请。
- 输入事实：申请状态和材料完整性来自审核申请记录。
- 当：申请处于待审状态且材料完整。
- 则：记录通过或驳回结论。
- Owner：运营负责人。
- 正例 / 边界例 / 反例：待审申请可裁决；终态重复提交保持原结果；非待审申请不得生成新结论。

产品接口抽象说明业务契约、输入、输出、失败语义和责任边界。

## 八、数据与风险

数据覆盖指标、报表、审计和追溯。风险和外部依赖均有业务确认方。

## 九、验收摘要

对应场景：SCN-001。

- 正常结果：审核结论、操作者和时间可查询。
- 关键边界：重复裁决不改变终态。
- 异常与兜底：材料来源不可用时停止裁决。
- 红线：不得生成无审计记录的审核结论。
