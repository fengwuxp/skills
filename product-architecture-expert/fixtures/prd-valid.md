## 阅读摘要

- 当前结论 / 为什么现在：审核积压且人工路径不清，本期统一审核入口和裁决口径，不改变交易处理。
- 产品定义 / 产品架构主脊：为运营提供可追踪的审核能力；审核申请 -> 审核任务 -> 裁决能力 -> 申请状态 -> R-001 -> 可查询结论。
- 本期承诺 / 非目标：承诺统一待审申请的裁决与审计；不修改结算规则或交易订单。
- 主链路 / 异常承接：提交、审核、通知；材料或外部来源不可用时保持待审并由运营承接。
- 关键待确认 / 责任与来源：材料来源可用性由运营负责人在评审结束前确认，未确认时禁止形成通过结论；事实源为本文件。

## 一、背景与问题

背景：审核积压影响运营；问题：人工路径不清，现状缺少统一入口。

## 二、目标与非目标

目标：缩短审核处理时间；非目标：不改结算规则。成功指标：当前审核中位处理时长基线为 24 小时，上线 30 天内目标降至 8 小时，观察窗口为上线后连续 30 天，Owner 为运营负责人。

## 三、定性与范围

- 定性对象：业务流程。
- 本期变化：治理。
- 责任边界：统一后台审核责任与可追踪结果，不承担交易处理。
- 范围：运营审核员使用，平台持有申请与审核事实，运营负责人拥有规则并验收；本期不处理交易订单。
- 架构：稳定点是申请、唯一当前结论和审计事实；材料来源可用性作为外部变化点，不预建通用规则平台。
- 取舍：总体判断是先统一审核口径；当前没有需要进入正文的第二套真实方案。

## 四、概要设计

- 方案概述：以审核任务承接待审申请，让审核员在统一入口形成唯一、可追踪的业务结论。
- 产品架构主脊：缩短审核时长 -> SCN-001 -> 审核裁决能力 -> 申请 / 审核任务及状态 -> R-001 -> 可查询且不可覆盖的结论。
- 核心能力：待审查询、材料核对、审核裁决、结果反馈、异常转人工和审计查询。
- 核心对象与关系：申请单产生一个当前审核任务；审核任务持有当前结论和审计记录，但不等于交易订单。
- 核心概念：审核任务；定义：等待运营判断的申请；不是什么：交易订单；归属主体：平台。
- 关键交互与边界：审核员裁决，平台保存事实，运营处理材料与外部来源异常；交易系统不接受本产品修改。
- 方案取舍：本期不建设通用工作流平台，待出现第二类已确认审核流程后复审复用边界。
- 关键图 / 不画图理由：无需单独画图；单场景、三状态和一条裁决规则可由本节主脊及第 6 节编号流程完整复述。

## 五、详细设计

以下场景说明申请单如何形成可追踪的审核结论。对象状态为待审、通过、驳回，生命周期从创建到关闭，不变量是一次申请只能有一个当前审核结论。

### SCN-001 运营审核申请

- 业务情境：审核员面对材料完整且状态为待审的申请，需要形成可追踪的审核结论。
- 责任推进：审核员核对材料并裁决，平台保存事实并反馈结果，运营承接材料或来源异常。
- 裁决与状态：依据 R-001，申请由待审变为通过或驳回；重复裁决保持原终态。
- 异常与收口：材料或来源不可用时保持待审并转人工；结论、操作者和时间可查询即完成。

### 产品需求陈述

- 需求名称 / 类型：保存唯一审核结论 / 功能。
- 责任主体 / 场景 / 前置状态：审核平台 / SCN-001 / 申请待审。
- 规范强度 / 行为或业务结果：必须 / 保存唯一当前结论并向审核员反馈。
- 度量、时限或边界：重复裁决不得改变终态。
- 来源与可靠性 / 关联规则 / 验收样例：已确认运营规则 / R-001 / 重复提交返回原终态和原审计记录。

## 七、业务规则与接口抽象

- 规则编号：R-001。
- 规则名称 / 性质 / 业务动机：待审申请裁决 / 场景裁决规则 / 防止终态被覆盖。
- 适用场景 / 步骤：SCN-001 / 审核裁决。
- 适用对象与范围 / 输入事实：待审申请 / 申请状态和材料完整性来自审核申请记录。
- 当 / 则 / Owner：申请待审且材料完整 / 记录通过或驳回结论并保留操作者和时间 / 运营负责人。
- 正例 / 边界例 / 反例：待审可裁决 / 终态重复提交保持原结果 / 非待审禁止生成新结论。

### 产品接口抽象

- 产品接口名称：审核申请裁决。
- 接口使用方：审核员使用该能力形成申请的当前审核结论。
- 接口输入与前置条件：待审申请、完整材料、审核权限和可用材料来源。
- 接口业务输出与副作用：返回通过或驳回结论，将申请置为对应终态并新增审计记录。
- 接口失败语义：非待审申请返回原结论且无新副作用；材料或来源不可用时保持待审并转人工。
- 接口责任边界：平台保存审核事实，运营确认材料来源并处理异常，交易系统不受该裁决直接修改。

## 八、数据与风险

数据覆盖审核时长指标、结论报表、操作者与时间审计和申请追溯。待确认项是材料来源可用性，Owner 为运营负责人，截止时间为本 PRD 评审结束前；未确认时保持待审并禁止形成通过结论，影响范围是审核上线。

## 九、验收摘要

对应场景：SCN-001。

- 正常结果：通过或驳回结论、操作者和时间可查询。
- 边界结果：重复裁决返回原终态，不生成新结论。
- 禁止结果：不得覆盖已经形成的终态。
- 失败后的可观察状态：材料来源不可用时保持待审并显示待人工处理。
- 恢复或人工处理：运营负责人补充材料来源后重新发起裁决。
- 数据、审计或运营证据：结论、操作者、时间和重复提交结果可查询。
- 验收 Owner：产品负责人和运营负责人。
