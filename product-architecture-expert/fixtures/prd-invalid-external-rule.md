## 阅读摘要

当前结论：统一外部资质审核入口。产品定义 / 产品视图：为运营提供可追踪的审核能力。主链路为提交、审核、通知；申请单由平台管理。

## 一、背景与问题

背景：外部资质审核缺少统一版本；问题：运营无法确认当前适用口径。

## 二、目标与非目标

目标：让外部资质审核使用同一有效版本；非目标：不替代专业审批。成功指标：当前版本不一致率基线为 12%，上线 30 天内降至 0%，Owner 为业务负责人。

## 三、定性与范围

产品定性：外部规则治理；总体判断：统一审核口径；范围是资质申请，不做范围是监管解释和最终专业判断。

## 四、概要设计

方案概述：围绕资质申请建立版本化审核入口。
产品架构主脊：统一外部规则 -> SCN-001 -> 资质审核能力 -> 申请状态 -> R-EXT-001 -> 可追踪结论。
核心能力：申请查询、版本化规则裁决、待专业确认和审计查询。
核心对象与关系：资质申请引用裁决所用规则版本，审核结论不等于监管审批结果。
核心概念：资质申请；定义：等待运营按外部规则判断的业务对象；不是什么：监管审批结果；归属主体：平台。
关键交互与边界：审核员处理，业务负责人确认规则适用性，平台只保存审核事实。
用户：运营；主体：平台；角色：审核员；验收方：产品和业务；责任边界：不替代专业审批。
关键图 / 不画图理由：无需单独画图；单场景状态变化可由编号流程复述。

## 五、详细设计

详细设计围绕资质申请对象展开，状态包括待审、通过、驳回和待专业确认，生命周期在形成可追踪结论后关闭，不变量是规则有效性不明时不得通过。

### SCN-001 运营审核资质申请

- 业务问题与期望结果：审核员使用当前有效外部规则形成可追踪结论。
- 参与者与责任：审核员处理，业务负责人确认外部规则适用性。
- 触发与前置事实：资质申请已提交且状态为待审。
- 主路径与状态变化：申请由待审变为通过、驳回或待专业确认。
- 适用规则：R-EXT-001 适用于资质裁决步骤。
- 完成证据与验收种子：审核记录可以查询规则编号和结论。
- 逆向、异常与停止：规则有效性不明时停止裁决并等待专业确认。

### 产品需求陈述

- 需求名称：阻止未确认规则自动批准。
- 需求类型：约束。
- 责任主体：审核平台。
- 场景 / 前置状态：SCN-001，申请处于待审状态。
- 规范强度：不得。
- 要求的行为或业务结果：规则有效性未确认时不得形成通过结论。
- 度量、时限或边界：所有通过结论都能回查所用规则版本。
- 来源与可靠性：业务负责人提出，待专业确认。
- 关联规则：R-EXT-001。
- 验收样例：缺少有效版本时申请保持待专业确认。

## 六、关键流程

主流程为提交、规则核对、审核、通知；异常流程处理规则失效；人工处理由专业 Owner 承接。

## 七、业务规则与接口抽象

- 规则编号：R-EXT-001。
- 规则名称：外部资质审核。
- 规则性质：版本化 / 外部规则。
- 业务动机：确保资质结论使用当前有效的外部规则。
- 适用场景 / 步骤：SCN-001 / 资质裁决。
- 适用对象与范围：资质申请。
- 输入事实：申请材料和规则有效性状态。
- 当：申请材料满足外部要求。
- 则：允许形成通过结论。
- Owner：业务负责人。
- 正例 / 边界例 / 反例：材料满足时通过；规则不明时待确认；材料缺失时驳回。

### 产品接口抽象
产品接口名称：资质申请裁决。接口使用方：审核员。接口输入与前置条件：待审申请、材料、审核权限和候选规则版本。接口业务输出与副作用：形成审核结论、记录规则版本并变更申请状态。接口失败语义：规则适用性不明时进入待专业确认且不形成通过结论。接口责任边界：平台保存事实，业务负责人确认外部规则，产品不替代专业审批。

## 八、数据与风险

数据覆盖规则编号、审核结果和审计。风险是外部规则失效，最终确认方为专业 Owner。

## 九、验收摘要

对应场景：SCN-001。

- 正常结果：有效规则下形成可追踪结论。
- 关键边界：规则有效性不明时保持待确认。
- 异常与兜底：转专业 Owner 人工确认。
- 红线：不得在规则有效性不明时形成通过结论。
