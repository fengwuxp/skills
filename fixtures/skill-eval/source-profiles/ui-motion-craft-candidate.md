本文件仅用于行为对照评测，不属于 `ui-design-expert` 的已安装 reference 或当前入口权威。评测时把它作为候选增量叠加到当前 `SKILL.md` 与既有 references；行为门通过后，才把正文与一条入口路由一起晋升到运行时。

候选入口路由：用户要求设计或审查 Web 动画、转场、微交互、拖拽、回弹、再次抓取、反向操作、弹簧、可中断交互、`Rubber-banding`、动效术语或减少动效体验时读取本文；静态信息层级、响应式或普通视觉设计继续使用既有 UI references。

# Web 动效与交互工艺

本文用于设计、筛选和审查 Web 界面的动效与手势交互。动效必须解释反馈、状态或空间关系，不以“高级感”“Apple 风格”或参数命中替代产品情境、现有设计系统和真实体验验证。

## 使用时机

- 用户要求设计或审查动画、转场、微交互、拖拽、滑动、弹簧、可中断交互或减少动效体验。
- 页面被评价为生硬、迟钝、过度动画或状态跳变，需要先判断哪些地方值得动、哪些必须保持静止。
- 需要把模糊动效描述转成可供产品、设计、前端和 AI 共同使用的准确术语。

## 不适用场景

- 当前问题属于信息架构、内容层级、权限、状态缺失或失败恢复，动效不会改变判断。
- 局部功能必须继承现有设计系统，且没有新增或调整动效的授权。
- 原生 iOS / Android 平台规范、已确认设计到代码的实现或普通前端性能修复；分别交对应平台能力或 `senior-software-architect`。

## 读取后必须产出

- 当前任务、操作频率、动效目的、现有 tokens / motion library 和不得改变的交互事实。
- 每个实际候选的 `采用 / 拒绝 / 待 feel-check` 判断；整站或页面级机会扫描同时记录真实存在的被拒候选和理由。
- 动效行为、可中断性、减少动效、性能与验证要求；精确值优先继承项目现有 token，不从外部示例硬编码。

## 1. 动效决策门

候选依次回答四个问题；任一项不成立就拒绝，不为完整而补动画：

1. **频率**：高频、键盘驱动和重复操作优先即时与稳定，通常拒绝装饰性转场；偶发弹窗、状态转换和首次体验才有更高动效预算。
2. **目的**：只接受反馈、空间连续、状态说明、避免突变、解释或低频愉悦。说不清目的时不加。
3. **等待成本**：动效不能阻止继续操作或让用户等待装饰。时长和 easing 继承项目 token；没有 token 时先形成候选并 feel-check，不把外部数值写成标准。
4. **功能影响**：数据密集、需要比较或高责任操作的内容不能为装饰而移动；危险操作、错误和完成状态必须先清楚，再决定是否需要动作辅助。

整站或页面级动效机会扫描应记录实际存在的被拒候选及理由；没有候选可拒绝时不凑数。全部拒绝也是有效结论。窄范围术语查询和单组件修复不强制生成被拒候选。

## 2. 审计与计划

先侦察再评价：

- 技术栈与 motion library；全局 CSS、tokens、duration、easing、spring 和手势约定。
- 产品情境与界面性格；任务型后台、内容阅读、品牌展示和游戏不能共享同一强度。
- 操作频率；高频导航、悬停、快捷键、偶发弹窗、首次引导分别判断。
- 已确认的设计决定、注释与例外；不得把有 Owner 的权衡重新报成缺陷。

审计覆盖目的与频率、缓动与等待、起点与 `transform-origin`、可中断与反转、渲染性能、减少动效、tokens 一致性和真实机会。每个 finding 必须回到页面 / 组件 / 状态或 `file:line`，由主审重新读取证据后再进入报告。

先按影响与修改成本排序，只为经确认的 finding 写自包含计划。计划说明现状、目标行为、继承的 token / primitive、范围、非目标和 feel-check；用户未授权实现时不改源码、不安装 motion library、不创建长期计划目录。

## 3. 交互正确性

- **即时反馈**：按下、拖动和状态变化应尽早给出视觉反馈，但不改变原生激活、键盘或焦点语义。
- **连续与可中断**：用户可控制的手势从当前屏幕状态继续，支持重新抓取、反转和重定向；固定 keyframes 或等待旧动画结束会破坏控制感。
- **速度与动量**：释放后的动作可以参考方向与速度，但阈值和 spring 参数必须由目标组件、输入设备、现有 library 和真实播放校准。
- **性能**：优先使用不会触发布局抖动的实现路径，并核对合成、重绘、长列表和低性能设备；`transform` / `opacity` 是常见起点，不是无条件限制。
- **减少动效**：响应 `prefers-reduced-motion`，提供无信息损失的替代表达；必要状态可以即时呈现或使用更弱的非空间变化，不能只删除动画后让关系和结果不可理解。
- **空间与退出**：浮层从触发位置或明确空间关系进入，退出路径与进入语义一致；模态、菜单、抽屉和 toast 不机械共享同一 origin。

## 4. 最小术语表

术语只用于正名和消歧，不自动产生设计决定：

| 术语 | 识别重点 |
| --- | --- |
| `Rubber-banding` | 越过边界后的渐进阻力与回弹 |
| `Origin-aware animation` | 元素从触发位置或关联锚点出现 |
| `Shared element transition` | 同一对象在两个视图间连续变形与移动 |
| `Continuity transition` | 用连续变化维持前后状态的方向感 |
| `Layout animation` | 布局变化时从旧位置连续到新位置 |
| `Stagger` | 多元素按顺序错开进入；高频任务默认克制 |
| `Spring` | 由物理参数收敛、可重定向的运动 |
| `Rubber-band / spring / bounce` | 三者分别描述边界阻力、收敛机制和视觉过冲，不混作“弹一下” |

用户只问“这个效果叫什么”时，先给最匹配术语，再给至多两个相邻词及差异；术语表没有精确匹配时明确近似，不发明名称，不顺手设计界面。

## 5. 输出契约

动效机会扫描或存在被拒项的审计报告使用最小两段；没有实际被拒候选时省略第二段：

```text
采用 / 待 feel-check：位置或状态 | 任务与频率 | 当前证据 | 动效目的 | 建议行为 | 继承项 | 验证
被拒候选：位置或状态 | 被哪一道决策门拒绝 | 理由
```

源码 Review 先给严重度、`file:line`、当前行为、任务影响和修复方向；没有实际项目和源码时不得虚构路径。实现计划中的精确参数来自项目已有 tokens、被测组件或明确候选，不能把外部示例伪装成项目标准。

## 6. 验证与停止

- 在真实浏览器或可操作原型中验证入口、退出、快速重复、反转、中断、拖拽释放、键盘、触控和 `prefers-reduced-motion`。
- 对需要判断节奏、bounce、crossfade 或空间连续性的动作，使用慢速或逐帧回看；代码和静态截图只能证明实现线索。
- 核对真实内容、加载 / 错误 / 禁用状态、桌面与移动视口及低性能条件；必要时由目标用户完成任务。
- 动效让操作变慢、掩盖状态、破坏焦点、造成眩晕、提高误触或无法从现有设计权威解释时停止并回退。
- 自动检查、motion token 命中和浏览器播放只提供局部证据，不证明产品语义、完整可用性、WCAG 符合或生产准入。
