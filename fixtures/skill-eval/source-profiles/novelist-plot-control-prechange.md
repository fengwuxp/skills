Purpose: baseline for distinguishing logical timeline structure from natural-time, causal-reachability, and target-stage admission.

## Existing plot and timeline contract

- Plot progression uses `goal -> action -> resistance -> choice -> result -> new situation`.
- Event time and presentation time remain separate. Stable event IDs, `T` anchors, `P` anchors, line roles, time relations, `Depends On`, `Interface`, and `State Delta` describe the logical timeline.
- `T` values are logical coordinates, not hours, days, distance, or healing time.
- Movement, messages, commands, waiting, recovery, and continuing states use natural duration when the task needs it. `unknown` is allowed when evidence is missing.
- Cross-line influence requires a message, person movement, resource transfer, shared environment, or meeting interface. Same-window and exact-sync do not create causality.
- `--require-ready` checks confirmed/aligned records and explicit `blocker:` tokens. It does not prove natural-time semantics, character knowledge, continuing-state correctness, or prose readiness.

## Existing admission behavior

The reference asks for structural, record, semantic, and stage conclusions, but does not provide a mandatory target-stage recipe that reclassifies ordinary `unknown` fields before a chapter-card or prose claim. `Depends On` remains an untyped completion dependency, and world-internal joins do not require an explicit observer, observable signal, earliest signal time, or fallback.

## Existing event card

The event card has one `required duration` field plus upstream conditions, character knowledge, action, result, downstream interface, and presentation position. It does not provide an on-demand multi-clock budget or a typed causal-edge card.
