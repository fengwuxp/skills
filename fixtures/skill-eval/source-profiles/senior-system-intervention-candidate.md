# 系统干预与回溯卡候选增量 r2

本文件仅用于行为对照评测，不是已安装 Skill、当前架构权威或发布准入证明。

## 使用边界

仅当问题同时具有症状反复、多主体、跨边界反馈、明显时间延迟，或局部修复可能转移成本时使用。根因已定位、路径线性、单点可逆且能由一个失败测试闭合的问题，直接修复，不展开系统图、前瞻或回溯推演。

## 系统干预与回溯卡

1. **察实与正名**：区分行为随时间的变化、当前事实、推断、待确认和系统边界；列出参与者、责任、被遗漏的声音和证据来源。图是待验证模型，不是因果事实。
2. **回路与延迟**：只选会改变决策的关键变量，标明同向或反向关系、强化环、平衡环、时间延迟和可能的政策阻力；无法回到证据时保持假设状态。
3. **前瞻而非预测**：未来不确定性会改变方案时，列出多个可能情景、早期信号和复核条件，不给单一路径的伪精确预测。
4. **回溯与前向校验**：目标态和 Owner 已确认后，再反推关键差距、里程碑、可控 / 部分可控 / 不可控因素与前置条件；随后从当前状态向前检查路径，暴露不一致、跳步和外部依赖。
5. **最小干预**：选择一个能检验核心机制的最小可逆动作，写清 Owner、反馈源、成功信号、失败信号、停止和回退。卡片没有改变干预位置或验证动作时立即丢弃，不为完整而补图。

触发后，下列字段是最低准入而不是可选提示：反馈问题显式写出强化环、平衡环和时间延迟；Backcasting 显式写出目标 Owner、可控性分类和前向校验；最小干预显式写出 Owner、观察窗口、成功 / 失败信号、停止与回退。证据不足时标为待确认或说明该回路不存在，不得用省略或虚构补齐。

## 最小输出

```text
问题行为与时间范围：
系统边界、主体与证据：
关键变量、关系与延迟：
强化环 / 平衡环 / 待证假设：
可能情景、早期信号与复核条件：
目标态、反推里程碑与可控性：
前向校验：
最小可逆干预、Owner、反馈与停止：
```

## 确定性结构门候选

仅在行为评测 candidate 中，把系统干预卡写成 JSON 后通过 stdin 交给：

```bash
python3 fixtures/skill-eval/candidate-tools/check_system_intervention_card.py < card.json
```

- `mode=feedback` 校验问题、证据、强化环、平衡环、延迟、杠杆点和最小干预。
- `mode=backcasting` 校验问题、证据、至少两个情景、早期信号、复核条件、Owner、可控性、前向校验和最小干预。
- `mode=combined` 同时执行两组校验。
- `problem.non_negotiable_constraints` 必须逐项收集用户任务与 source 明示的不可退让边界，例如唯一权威、授权、安全、可访问性、失败恢复和证据边界；不得用 `N/A`、概括性“遵守红线”或遗漏代替，渲染时原样保留。
- 退出码 `0` 时必须以报告中的 `rendered_markdown` 作为最终回答骨架，不得再次摘要掉强化环、平衡环、延迟、可控性、Owner、观察窗口、信号、停止或回退字段；允许去除与当前 mode 无关的章节，不改变事实状态和证明边界。
- 退出码 `0` 只证明字段结构完整；`1` 表示结构缺失；`2` 表示输入不是合法 JSON。报告固定声明 `proof_limit=structure_only`；`rendered_markdown` 只是确定性转写，不得据此声称因果成立、方案正确、已获授权或可生产准出。

该脚本仍是候选评测资产，不是已安装 Skill 的运行时入口。根因已定位的线性局部 Bug 不构造此卡，也不调用该脚本。

## 来源边界

- 微信文章《系统思维：解决复杂问题的7种工具》只作为二次整理入口，不作为完整方法或有效性证据。
- 英国 Government Office for Science 的 Systems Thinking Toolkit 与 Futures Toolkit 用于校准因果回路、系统边界、Backcasting 和可控性。
- WHO 的 Causal Loop Diagrams 课程用于校准强化 / 平衡回路、时间延迟和杠杆点。
- OECD Strategic Foresight 用于校准“多个可能未来，不预测唯一未来”。
- 华夏经世智慧只提供察实、正名、审时、权衡、行验与知止镜片，不替代专业事实、测试、CR 或 Owner。
