# 小说器物视觉设计单成图设计

## 1. 目标

在现有候选 Skill `fiction-visual-designer` 中增加“器物成图模式”，把已经确认的器物视觉设计单转成可复核的多视图图片包。

本设计不新建顶层 Skill，不重新实现图片模型调用，不引入供应商、API Key 或默认联网能力。`fiction-visual-designer` 负责领域成图编排与视觉验收，系统 `imagegen` 继续负责实际图片生成、参考图生成和局部编辑。

本文件只约束器物成图扩展。`docs/superpowers/specs/2026-08-19-fiction-visual-designer-design.md` 仍是通用视觉设计、正典边界和对象方法的权威；两者发生交叉时，本文件只在“已确认器物设计如何成图”范围内补充执行契约。

## 2. 方案决策

采用增强现有 `fiction-visual-designer` 的方案：

```text
已确认器物设计单
  -> fiction-visual-designer 编译视图任务与不变量
  -> imagegen 分别生成或修订图片
  -> fiction-visual-designer 检查结构与跨图一致性
  -> 本地脚本确定性拼版
  -> 已验收器物视觉设计单
```

不采用以下方案：

- 不新建 `fiction-artifact-renderer`：当前职责只是现有视觉契约到 `imagegen` 的领域编排，新增顶层 Skill 会重复触发、metadata、fixture 和准入门禁。
- 不建立供应商图片生成 Skill：系统 `imagegen` 已持有模型、提示词适配和生成执行；重复实现会引入密钥、费用、联网和版本治理。
- 不让模型一次生成带中文标注的完整设计单：模型内文字和跨视图结构不稳定，分视图生成后确定性拼版更可验证。

## 3. 职责边界

| 能力 | 持有职责 | 不得越界 |
| --- | --- | --- |
| `novelist` / 作者 | 器物来历、能力、代价、人物关系和正典状态 | 不因成图便利修改故事事实 |
| `fiction-visual-designer` | 设计状态检查、视图任务、不变量、跨图连续性、生成结果验收 | 不选择供应商，不直接实现模型 API，不把图片自动升级为正典 |
| `imagegen` | 可用模型选择、提示词适配、参考图生成、编辑和图片保存 | 不反向修改器物身份、结构、材质和能力规则 |
| 拼版脚本 | 缩放、留白、排序、ASCII 标签和 PNG 输出 | 不重绘、修饰、生成或解释图片内容 |

“纯图片生成”仍由 `imagegen` 主责。只有请求涉及已确认器物视觉设计单、多视图结构、跨图连续性或按设计单验收时，才进入 `fiction-visual-designer` 的器物成图模式。

## 4. 输入门禁

不新增独立 JSON schema，直接消费现有视觉设计单。开始生成前必须取得：

```text
状态：已确认设计
对象类型与用途：
不可变锚点：
结构、比例和主要部件：
材质、工艺与当前状态：
尺度参照：
必须可见：
禁止新增与特效禁区：
输出用途：预览 / 项目资产
```

门禁规则：

- `视觉候选` 不授权图片生成。用户要求“设计并画出来”时，先确认视觉设计，再进入成图。
- 缺少的信息只有在会改变对象类型、主结构、材质、状态或视图任务时才询问一个关键分叉。
- 用户要求精确尺寸、制造图、CAD、真实正投影或可直接交付 3D 建模的工程图时停止；生成式图片只能交付视觉概念设计单。
- 参考图片按身份锚图、结构参考、材质参考或构图参考明确分工，不把未知来源图片当正典或许可证明。

## 5. 默认交付

第一版默认输出：

```text
01-front.png
02-side.png
03-three-quarter.png
04-detail.png
artifact-design-sheet.png
artifact-beauty.png       # 可选，仅在用户需要展示图时生成
```

四张源图分别承担：

| 视图 | 任务 |
| --- | --- |
| 正面 | 检查对称关系、主要轮廓、正面连接与部件数量 |
| 侧面 | 检查厚度、弧度、重心、截面趋势和前后关系 |
| 3/4 | 作为身份锚图，综合展示体积、材质、工艺与当前状态 |
| 结构细节 | 展示最关键的连接、握持、鞘装、工作面或发动媒介 |

展示图用于表现使用情境、氛围和视觉吸引力，不能替代四视图、遮盖结构问题或成为正典依据。

第一版不新增持久化 manifest。最终响应必须报告图片绝对路径、实际提示词或提示词集合、使用的生成路径、验收结论和未验证限制。

## 6. 生成循环

1. **预检**：确认设计状态、输入门禁、`imagegen` 可用性、输出用途和写入位置。
2. **编译任务**：从设计单抽取四个视图共享的不变量，以及每个视图必须显露的结构。
3. **生成锚图**：先生成无文字、无水印、均匀光照、中性背景的 3/4 图。
4. **验收锚图**：检查对象类型、轮廓、主要结构、材质、工艺、尺度感和状态；承重偏差未关闭前不生成其余视图。
5. **生成分视图**：以通过的 3/4 图作为身份参考，分别调用一次 `imagegen` 生成正面、侧面和结构细节图。不同视图使用不同任务，不用同一提示词的随机 `n` 张变体代替。
6. **跨图验收**：检查部件数量、长宽厚比例、结构连接、材质、纹样、磨损、损伤和神异状态是否一致。
7. **最小修订**：单图失败时只修订该图，明确只改变视角或错误部位，其余不变量保持不变。
8. **停止重试**：每张图最多一次针对性重修；再次失败则报告模型限制，不无限消耗生成次数，也不降低设计标准。
9. **确定性拼版**：四图通过后运行拼版脚本，形成固定 `2x2` PNG 设计单。
10. **可选展示图**：最后使用已验收锚图和设计契约生成展示图，并单独验收。

## 7. 提示词交接

`fiction-visual-designer` 只形成媒介中立任务，不写死供应商、模型、种子或私有参数。每个视图的交接至少包含：

```text
画面任务：
对象与数量：
共享不变量：
当前视图必须可见：
材质、工艺与状态：
中性背景与参考光线：
允许探索：
禁止新增：
不得出现文字、水印、结构遮挡和无依据特效：
可观察验收条件：
```

具体模型语法、参考图片传递方式、输出尺寸和编辑参数由当前 `imagegen` 根据真实工具能力决定。模型或工具不支持参考图、编辑或所需尺寸时必须报告，不得发明调用方式。

## 8. 拼版脚本

新增 `fiction-visual-designer/scripts/compose-design-sheet.py`，只承担以下确定性动作：

- 读取四张 PNG、JPEG 或 WebP 源图。
- 按 `FRONT / SIDE / 3Q / DETAIL` 固定顺序排列为 `2x2` 网格。
- 等比缩放并居中，不裁掉主体，不拉伸比例。
- 添加固定边距、分隔线和 ASCII 标签。
- 输出 RGB 或 RGBA PNG，不覆盖输入文件。
- 输入缺失、图片损坏、输出路径无效或 Pillow 不可用时以非零状态失败。

脚本使用 Pillow，不自动安装依赖。运行时先使用当前 Python；Pillow 不可用时，可以读取 Codex Desktop 提供的 bundled workspace dependency Python。当前环境的 bundled Python 已验证包含 Pillow `12.3.0`。其它环境仍不可用时保留四张源图并报告拼版阻塞。

脚本提供 `--self-test`，在临时目录生成不同尺寸的色块图，断言视图顺序、输出尺寸、等比缩放和 PNG 格式。测试不访问网络，不读取项目私有文件，不留下持久化产物。

## 9. 失败与停止

| 失败 | 处理 |
| --- | --- |
| 设计未确认 | 停止生成，返回缺失确认项 |
| `imagegen` 不可用 | 返回媒介中立任务包和工具阻塞，不用 SVG、HTML 或占位图冒充成图 |
| 锚图对象误认或主结构错误 | 只允许一次最小修订；仍失败则停止其它视图 |
| 单个分视图漂移 | 只修订失败视图，保留已经通过的图片 |
| 跨图无法收敛 | 返回通过项、冲突项和模型限制，不拼版为“已验收” |
| Pillow 不可用 | 保留四张源图，不安装依赖，不声称设计单图片已完成 |
| 图片分辨率、遮挡或视角不足 | 标为无法验证并说明需要补什么 |
| CAD、制造或真实正投影要求 | 明确超出生成式视觉概念图边界，停止交付伪精确结果 |

## 11. 验证设计

### 11.1 确定性验证

- frontmatter 只包含 `name`、`description`。
- `SKILL.md` 能一层直达新 reference、脚本和既有设计单模板。
- 全仓 `scripts/validate.sh` 只对拼版脚本执行 `python3 -m py_compile`，并继续校验行为 fixture；不得让统一校验依赖 Codex Desktop 的绝对运行时路径。
- 当前任务通过 `codex_app__load_workspace_dependencies` 发现 bundled Python，再执行 `compose-design-sheet.py --self-test`；其它环境只有在可用 Python 已提供 Pillow 时才执行运行时自测。
- 拼版脚本对缺文件、坏图和不可写输出返回非零状态。
- reference index、source map、YAML、触发路径和同步 dry-run 通过。

### 11.2 行为 fixture

至少增加三个场景：

1. 已确认器物设计并明确要求出图：进入四视图生成与拼版，不只返回提示词。
2. 视觉候选尚未确认却要求直接出图：停止生成并请求确认，不把图片当成设计批准。
3. 要求精确 CAD、制造尺寸或真实正投影：说明视觉概念图边界，不伪装完成。

现有纯图片生成、故事正典、器物验图和组合交接场景必须继续通过，不让新模式吞并 `imagegen` 或 `novelist`。

### 11.3 真实图片试跑

选择两个不同结构的器物：

- 一柄有明确剑制、剑鞘和握持关系的剑。
- 一个非兵器器物，例如丹炉、药箱、身份令牌或灯具。

每个对象生成四张源图和一张拼版。程序检查文件非空、图片可解析、尺寸符合约束、四个视图齐全；独立视觉 Checker 按设计单检查对象类型、主要结构、部件数量、比例、材质、纹样、状态和跨图一致性。

同一 runner/model 的 baseline 与 candidate 必须重复执行并盲评。静态 fixture、脚本自测、图片存在或 Agent 自述都不能单独关闭 `FVD-001`。

## 12. 来源与吸收边界

- `inference-sh/skills` 的 `character-design-sheet`：只吸收“分视图生成后拼接”和参考锚点方法；不吸收人物专属流程、`allowed-tools`、外部 `belt` CLI 或安装命令。
- `krea-ai/skills` 的资产单流程与 issue `#30`：只吸收资产单先行、确认后进入下游场景和用已批准图片作参考；不引入 Krea MCP、账号、费用或完整影视流水线。
- 80.lv《Concept Art for Clients: From Brief to Delivery》：只吸收展示图与功能拆解图分离、最少灯光、基础材质、多角度和机械结构交付；不复制文章、图片或作者表达。
- OpenAI Image Generation 官方文档：只作为参考图、多轮编辑和输出能力的当前官方依据；实际运行仍以当前会话暴露的 `imagegen` 和工具能力为准。

实现时把上述来源追加到 `fiction-visual-designer/references/source-map.md`，记录读取日期、适用范围、许可或使用边界和拒绝内容，不把外部仓库作为运行时依赖。

## 13. 完成标准

- 用户可以从一份已确认器物设计单取得四张独立视图和一张确定性拼版 PNG。
- 生成前确认设计状态，生成后按同一设计契约验收。
- 四视图共享对象身份、主要结构、材质和状态；失败视图只做一次最小修订。
- 展示图不替代功能设计图，生成结果不反向修改正典。
- 缺少生成工具、Pillow 或精确制图能力时明确失败，不安装、不伪造、不无限重试。
- 没有真实图片试跑、重复执行与独立盲评时，Skill 保持 `candidate`，不得安装、同步、团队共享或公开发布。

本规格通过只授权后续形成实施计划，不等于授权图片生成费用、安装、Git、同步或发布。
