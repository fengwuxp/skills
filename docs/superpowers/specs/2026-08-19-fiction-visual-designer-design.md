# 小说视觉设计 Skill 吸收设计

## 1. 目标

新增通用专业 Skill `fiction-visual-designer`，把小说正典、故事意图或独立创意转化为可审查、可持续迭代、可交给图像生成能力执行的视觉设计契约。

首个专项 reference 面向仙侠、玄幻、武侠等东方幻想场景，覆盖人物、服饰、建筑、兵器、器物、灵药、灵物与灵兽。该专项不以固定风格词或提示词代替设计，而以实物结构、文化语境、故事功能、有限幻想变形和可见代价共同约束视觉结果。

## 2. 适用边界

`fiction-visual-designer` 负责：

- 设计或审查叙事作品中的人物外形、服饰、环境、建筑、兵器、器物、植物、药物、灵物和生物。
- 建立跨对象共享的视觉母题、结构、材质、色彩、纹样和状态连续性。
- 把已确认的故事语义转成媒介中立的视觉设计单和生成交接规格。
- 区分真实依据、传统表达、合理推演和文学虚构。
- 对生成图片进行结构、材质、状态、连续性和视觉方向验收。

本 Skill 不负责：

- 创作小说正文、决定人物命运、补写器物来历或改变故事因果。
- 把视觉候选自动升级为小说正典。
- 直接承担模型调用、供应商提示词适配或图片生成。
- 设计 Web UI、游戏界面或产品交互。
- 只做服制、建筑、兵器、植物或艺术史考证。
- 整理已经确认的正式设定集、DOCX 或 PDF。
- 默认联网、安装依赖、写入记忆、自动学习、执行 Git、同步或发布。

## 3. 职责与权威

作者是价值与正典的最终 Owner。各能力只在自己的职责内承责：

| 能力 | 持有职责 | 不得越界 |
| --- | --- | --- |
| `novelist` | 故事语义、正典状态、人物与器物关系、能力规则、代价、经历和连续性 | 不代替视觉 Skill 决定结构、材质、构图与跨图一致性 |
| `fiction-visual-designer` | 视觉母题、形制、比例、结构、材质、纹样、色彩、磨损、状态与视觉验收 | 不创造或修改故事正典，不直接调用生成模型 |
| `imagegen` | 模型选择、提示词适配、图片生成与变体 | 不根据生成便利反向改变故事语义或视觉契约 |
| `document-authoring` | 已确认视觉设定的正式整理与载体生成 | 不创造故事事实或视觉设计 |

协作链如下：

```text
novelist / 作者
  -> 故事语义包
fiction-visual-designer
  -> 已确认的视觉设计与生成规格
imagegen
  -> 图片与必要生成信息
fiction-visual-designer
  -> 视觉验收结论
novelist / 作者
  -> 必要的正典裁决与权威写回
```

新 Skill 可以处理没有小说项目的独立视觉请求；此时所有新增故事含义都保持视觉候选，不伪装成既有正典。

## 4. 触发与非触发

### 4.1 正向触发

- 为小说、漫画、影视、动画或游戏叙事设计人物、服饰、场景、建筑、兵器、器物、植物或生物。
- 建立一部作品或一个阵营的视觉设定、视觉母题或跨资产一致性。
- 把人物档案、世界设定、故事片段或器物经历转成视觉设计单。
- 延展同一对象的时期、季节、损伤、修复、成长或使用状态。
- 审查概念图、设定图或生成图片是否符合既定视觉契约。

### 4.2 硬负例

- “写一段秋水剑交战正文”：由 `novelist` 主责。
- “按这份已确认设计生成一张图片”：由 `imagegen` 主责。
- “设计仙侠题材管理后台”：由 `ui-design-expert` 主责。
- “考证战国剑的形制与铭文”：属于史实与器物研究，不触发本 Skill。
- “把确认后的角色和器物设定整理成设定集”：由 `document-authoring` 主责。

同时包含故事设计、视觉设计和图片生成时，按权威顺序依次交接，不把多个职责压成一个大而全流程。

## 5. 输入契约

开始时只确认会改变视觉方向的字段：

```text
任务模式：独立设计 / novelist 交接 / 现有设计审查 / 生成结果验收
设计对象：
叙事功能与使用者：
权威来源及设定状态：
必须保留：
允许改变：
未知或待确认：
历史文化边界：
目标载体：概念设计 / 设定集 / 影视 / 游戏 / 图片生成
```

存在小说项目时，必须继承项目权威、正典状态和不得改变项。缺失信息只有在会改变主方向时才询问一个关键分叉；不影响方向的缺口可以作为可替换候选继续设计。

## 6. 通用设计模型

所有对象共用五条设计轴，不为每类对象建立重复流程：

1. **叙事身份**：对象是谁、属于谁、服务什么行动、关系或读者认识。
2. **结构与功能**：对象怎样构成、活动、使用、生长或承受力量。
3. **材质与工艺**：对象由什么制成、怎样制造、加工、维护、衰败和修复。
4. **环境与关系**：地域、气候、生态、制度、阶层、职业和使用者怎样改变对象。
5. **状态与连续性**：初始、使用、损伤、修复、成长和跨时期状态怎样保持身份可辨。

对象专项只补充当前类别特有的判断：

| 类别 | 专项检查 |
| --- | --- |
| 人物 | 身份锚点、身体比例、轮廓、运动方式、年龄和经历状态 |
| 服饰 | 层次、裁剪、材料、职业与等级、气候、动作空间和穿用痕迹 |
| 建筑与环境 | 选址、结构、尺度、交通、仪式、权力关系、生活和修缮痕迹 |
| 兵器与器物 | 器类正名、受力、握持、重心、材质、工艺、鞘装、维护和损伤；载文、符印、凭证与术式媒介另行分型 |
| 植物与灵药 | 原植物、形态、栖息地、生长周期、药用部位、采制和生态关系 |
| 灵物与灵兽 | 骨骼、运动、食性、栖息地、生命周期、人与其关系及力量代价 |

## 7. 核心流程

1. **继承权威**：读取正典、不得改变项、未知项和目标载体；不以视觉完整度补写故事事实。
2. **判定任务**：区分整体视觉体系、单件设计、状态延展、连续性审查和生成验收。
3. **建立母题**：从故事功能、文化语境、材质、结构和母题形成视觉方向；只有真实分叉才给 2-3 个候选并推荐一个。
4. **完成五轴设计**：使用通用五轴，再加载对象类别和题材专项检查。
5. **标注证据**：区分真实依据、传统表达、合理推演和文学虚构；无法取得一手证据时停止声称史实。
6. **锁定连续性**：明确不可变锚点、允许变化、状态阶梯和负面约束。
7. **形成设计单**：先交视觉候选；作者确认后才形成生成交接规格。
8. **验收生成结果**：按设计契约检查图片；模型能力不足时报告工具限制，不擅自降低正典或设计标准。

## 8. 状态模型

视觉工作状态与小说设定状态分开维护：

```text
视觉候选 -> 已确认设计 -> 已验收图像
```

- **视觉候选**：可讨论、可替换，不是正典，也不授权生成。
- **已确认设计**：作者已接受视觉契约，可以交给 `imagegen`；是否写入小说权威仍按项目正典流程处理。
- **已验收图像**：图片符合视觉契约，只证明视觉实现，不证明故事语义、史实或发布准入正确。

任何生成结果都不能仅因“看起来更好”而反向晋升为已确认设计或小说正典。

## 9. 交接契约

### 9.1 `novelist` 到视觉 Skill

传递故事功能、人物或器物关系、能力与代价、经历状态、作者确认项、不得改变项和权威指针。不要求 `novelist` 预先完成形制、材质或构图设计。

### 9.2 视觉 Skill 到 `novelist`

只回传可能影响身份、历史、能力、象征、人物选择或连续性的视觉候选与冲突。纯造型细节不要求 `novelist` 重复裁决；作者确认后，由项目正典流程决定是否写回权威。

### 9.3 视觉 Skill 到 `imagegen`

传递媒介中立的构图目标、主体结构、材质、色彩、视角、状态、环境关系和负面约束。供应商、模型和参数适配由 `imagegen` 负责。

### 9.4 `imagegen` 到视觉 Skill

返回图片和必要生成信息。视觉 Skill 检查结构漂移、对象误认、材质错误、状态不一致和视觉方向偏离，并区分设计问题与工具限制。

## 10. 东方幻想专项

`references/eastern-fantasy.md` 采用以下来源优先级：

```text
博物馆实物、传统工艺、植物与建筑数据库
> 专业研究及可靠图录
> 成熟项目的美术复盘
> 外部 Skill 的抽象方法
> 搜索摘要、风格标签和模型记忆不得作为事实
```

专项转换链为：

```text
真实原型
-> 结构与工艺
-> 文化母题及使用边界
-> 故事功能
-> 有限幻想变形
-> 可见代价、磨损与历史痕迹
```

神兵、法宝与关键器物在通用五轴之内增加可选的“四镜五层”视觉转译：神话与礼仪、历史实物、建筑营造、工器制作四类证据，分别约束器类与职事、器骨与接合、材料与成器、灵机与行用、状态与承续。该方法只翻译上游已确认的器物事实，不建立五行配色、器灵成长树、统一品阶或战技表。

篆文、铭文、云纹、祥纹、符箓、印玺、符节、图箓、碑刻与阵图不统称为装饰纹样。专项先区分载文构件、纹样与文饰工艺、凭证验合器、术式媒介和空间型工器，再分别检查文字、母题与组织、载体、制作、所在部位、可读者、权限、接口、发动、损耗与历史改造；宗教语境中的效力陈述不能自动成为史实或小说能力。

专项必须守住以下边界：

- 兵器先正名并核对结构与使用方式，明确剑不是刀。
- 文化母题必须说明来源语境，不随机堆叠龙凤、饕餮、云雷纹等符号。
- 建筑必须能够解释结构、交通、仪式、生活和维护，不把巨构等同东方幻想。
- 灵药必须能回到植物形态、生境、药用部位、采制和生态影响。
- 灵物与灵兽必须能够解释身体、运动、食性、生境、生命周期及其力量代价。
- 不把长发、宽袍、悬浮、云海、发光纹路或“水墨风”作为默认答案。
- 不用颜色、宝石、粒子、材质数量和不可能结构表达装备稀有度。

## 11. 三级加载与文件结构

```text
fiction-visual-designer/
├── SKILL.md
├── admission.json
├── agents/
│   └── openai.yaml
├── references/
│   ├── visual-design-method.md
│   ├── eastern-fantasy.md
│   └── source-map.md
└── assets/
    └── visual-design-sheet-template.md
```

- Level 1 metadata 只承担视觉设计和审查的触发识别，并明确正文、生成、UI、纯考据和正式成文的非触发边界。
- Level 2 `SKILL.md` 只保留定位、五轴流程、状态、交接、场景路由和红线。
- Level 3 按任务读取通用方法、东方幻想专项、来源索引和设计单模板。
- 第一版不新增脚本。当前核心依赖语义判断与人工视觉验收，没有证据支持建立自动评分器或提示词生成器。

`admission.json` 初始状态为 `candidate`，`agents/openai.yaml` 设置 `allow_implicit_invocation: false`。只有结构、触发、相邻能力边界和真实行为证据通过独立评审后，才允许转为 `installable` 并评估隐式调用。

`novelist` 与 `imagegen` 是按任务协作的相邻能力，不是本 Skill 的安装硬依赖。仓库级配套只增加根 `README.md` 的能力路由和 `fixtures/skill-eval/fiction-visual-designer-behavior-cases.json`；这些文件不复制 Skill 正文或领域知识。

## 12. 来源吸收边界

| 来源组 | 只吸收 | 不吸收 |
| --- | --- | --- |
| `art-bible` 与 `asset-spec` | 跨对象视觉语法、单件设计单和验收字段 | 游戏项目目录、Agent 编排、GDD 依赖和工作室流程 |
| `character-scene-design` | 身份锚点、三视图、服装状态和固定道具连续性 | 刻板人物模板、个人路径、自动学习、品牌水印和伪评分 |
| `xianxia-visual-director` | 空间层次、构图、尺度、光色和材质检查 | 固定五层空间、禁止栏杆、背身仙人和巨构默认值 |
| `systemic-worldbuilding` | 资源、生态、聚落和社会后果的推演接口 | 默认文件写入、厚重世界百科和运行时依赖 |
| 博物馆、工艺、建筑、植物与动物资料 | 实物结构、材料、工艺、形态、生态和时代边界 | 原文、原图、未经核验推断和跨时代拼贴 |

`references/source-map.md` 必须为每个来源记录实际读取状态、页面或提交锚点、核验日期、适用范围、许可和未吸收内容。许可证不明的外部 Skill 只能提供可独立验证的抽象方法线索，不复制其原文、模板、提示词、代码或目录结构。

## 13. 失败与停止

- 正典冲突：停止设计落地，回交冲突、影响项和最小裁决问题。
- 关键输入缺失：只问一个会改变方向的主分叉；其余内容保持可替换候选。
- 史实证据缺失：标为文学虚构或待核验，不补写拟古事实。
- 来源冲突：保留版本、地域、时代和适用范围差异，不拼成单一结论。
- 生成失败：区分设计冲突、模型限制和参数问题，不通过修改正典掩盖失败。
- 跨对象风格漂移：回到共享视觉母题和不可变锚点，不为每个对象追加孤立风格词。
- 用户只要求探索：停在视觉候选，不强制收敛、生成或写回。

## 14. 最小交付

```text
设计结论：
继承的正典与状态：
视觉母题：
结构 / 功能 / 材质 / 环境 / 状态：
不可变锚点与允许变化：
事实、推演与虚构边界：
负面约束：
待作者确认：
生成交接规格（仅在设计确认后）：
验收标准：
```

输出按当前任务裁剪，不机械填满所有字段。单件器物不要求建立整部作品的视觉圣经；多对象确实共享语法时才先建立整体视觉母题。

## 15. 验证设计

### 15.1 正向行为样例

至少覆盖：

1. 有正典约束的秋水剑设计。
2. 同一角色跨时期的服装状态设计。
3. 宗门人物、建筑和器物的共享视觉语法。
4. 有植物学原型的灵药设计。
5. 有生态与运动依据的灵兽设计。
6. 对生成图片进行结构和连续性验收。
7. 不显式提及 Skill 名称的视觉设计请求。
8. 篆文、云纹与祥纹、凭符和碑刻共同参与启闸的载文、纹样和验合工器设计。

### 15.2 硬负例与混淆样例

至少覆盖小说正文、纯图片生成、仙侠 UI、纯史实考证和正式设定集整理。组合请求还要证明当前 Agent 能按 `novelist -> fiction-visual-designer -> imagegen` 顺序交接，而不是让任一能力吞并全流程。

### 15.3 准入证据

1. **结构校验**：YAML、frontmatter、引用、目录、source-map 和同步 dry-run。
2. **行为校验**：正向触发、隐式触发、硬负例、正典越权、输出契约和相邻 Skill 混淆。
3. **质量验证**：用同一 runner/model 对 baseline 与 candidate 任务重复执行，再由不知道候选目标的评审者盲评真实产物。

结构通过、fixture 合法或 Skill 自述不能替代真实行为改善。行为失败时先区分触发、职责、来源、流程、输出和验证问题，只修改能回到失败证据的最小位置。

## 16. 第一版完成标准

- `fiction-visual-designer` 的职责、触发与非触发不与 `novelist`、`imagegen`、`ui-design-expert` 和 `document-authoring` 重叠。
- 通用五轴方法能够覆盖首批六类对象，不依赖题材风格词。
- 东方幻想专项能从一手结构与文化依据形成有限幻想变形，并保留事实与虚构边界。
- 视觉候选、已确认设计和已验收图像不会被混成小说正典或生成授权。
- 外部来源的许可、时效、实际读取状态和拒绝内容可回查。
- 正向、硬负例和组合交接行为取得独立可复核证据。
- 第一版不包含第二题材专项、供应商适配、自动提示词生成、自动评分、自动写回、安装、同步、Git 或发布。

本设计完成后才允许另建实施计划；规格通过不等于实现、安装或可用性准入。
