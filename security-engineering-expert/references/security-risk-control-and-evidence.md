# 安全风险、控制与证据

## 使用时机

需要形成安全设计、威胁/滥用评审、控制矩阵或发布安全门禁时读取。本文给出共同骨架，不替代场景专项事实。

## 不适用场景

- 不用于凭关键词给系统打“安全分”。
- 不用于替代漏洞扫描、渗透测试、法律合规判断或生产授权。

## 读取后必须产出

- 资产与资损、主体与信任边界、威胁与滥用路径、控制与恢复、验证证据、残余风险与停止条件。
- 每条高风险路径至少有一个控制 Owner 和一个可复核证据；没有证据时标记未验证。

## 需要继续读取的 reference

- 先在 `security-scenario-routing.md` 选择主场景。
- 使用外部标准或版本化要求时读 `source-map.md`。

## 风险链

用一条可复核的因果链描述风险：

```text
资产 -> 资损/安全后果 -> 威胁或滥用主体 -> 前提与入口
     -> 跨越的信任边界 -> 动作与传播 -> 现有控制及失效方式
     -> 预防/检测/响应/恢复 -> 验证证据 -> 残余风险与 Owner
```

不要只列“注入、越权、泄露”等名词。路径必须说明攻击者或误操作者如何从入口到达资产，以及控制在哪个节点阻断、发现、限制或恢复。

## 资产、主体与边界

- **资产**：数据、资金、凭证、身份、权限、业务资格、配置、代码、制品、服务可用性、审计证据和组织信誉。
- **资损/后果**：直接资金损失、数据泄露或篡改、未授权能力、业务中断、证据丢失、合规责任和不可恢复状态。
- **主体**：外部攻击者、合法低权限用户、内部人员、管理员、服务身份、第三方、设备、任务和 AI/自动化代理。
- **信任边界**：公网/内网、租户、组织、权限域、服务、数据域、运行环境、第三方、构建发布和人工审批边界。

先确认权威身份与责任，不从客户端字段、网关 Header、网络位置、历史 token 或任务自述推断可信。

## 威胁与滥用路径

至少从下列角度选择与当前资产有关的路径：

- 伪造、账户接管、权限提升、对象/数据越权和职责串用。
- 篡改、注入、消息伪造、重放、乱序、重复、竞态和幂等冲突。
- 敏感数据过度采集、跨域泄露、日志/导出泄露、密钥暴露和不安全销毁。
- 业务流程绕过、额度拆分、批量滥用、异常退款/放款、内部合谋和审计规避。
- 第三方、依赖、构建、制品、配置、发布权限和运维通道失陷。
- 拒绝服务、资源耗尽、告警失效、恢复失败和证据被破坏。

## 控制闭环

| 层次 | 回答的问题 | 典型证据 |
| --- | --- | --- |
| 预防 | 如何减少发生概率或限制入口 | 默认拒绝、最小权限、输入/协议校验、隔离、审批、签名、限额、不可变策略 |
| 检测 | 如何在损失扩大前发现 | 安全日志、指标、异常规则、完整性校验、配置漂移、对账、关联告警 |
| 响应 | 发现后谁在多长时间内做什么 | 分级、隔离、冻结、吊销、阻断、人工接管、证据保全、通知与决策记录 |
| 恢复 | 如何回到可信状态并防止复发 | 回滚、密钥轮换、数据/账务修复、重放校验、对账、演练、复盘和回归门禁 |

控制需记录作用点、Owner、失败模式、旁路、依赖、业务代价和验证方式。高风险控制若只存在于文档、前端提示、未启用配置或无法回读的流程中，视为未落地。

## 验证证据

分层声明，不跨级声称：

1. `D1 Design`：不变量、路径、控制和验收已定义。
2. `D2 Implementation`：代码、配置、策略或基础设施已实现并可定位。
3. `D3 Enabled`：目标环境已加载/启用，配置与权限可回读。
4. `D4 Runtime`：测试、扫描、日志、告警、故障注入或演练证明控制按预期工作。
5. `D5 Production`：目标生产版本、真实依赖、观测窗口、Runbook、值守与风险 Owner 完整。

扫描无发现只是一类证据；测试、配置回读、制品来源、运行观测和人工演练按风险组合。任何证据必须带目标、版本/时间、结果和保管位置。

## 残余风险与准出

- `READY`：关键路径、控制和所需证据闭合，未发现阻塞风险；仍不等于法律合规或永久安全。
- `READY_WITH_RISK`：残余风险已量化或定性，补偿控制、期限和接受 Owner 明确。
- `BLOCKED`：关键资产/责任未知、重大路径无控制、控制未启用/未验证、恢复不可用，或风险无人接受。

正式结论至少写明残余风险、Owner、截止时间、复核触发器和停止条件。风险接受不能由设计者、实现者或 Agent 代签。
