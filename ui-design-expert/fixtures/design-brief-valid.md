# 对账异常工作台设计契约

## 事实、目标与边界

用户与场景：财务运营每日高频处理渠道对账异常。主任务是定位差异、补充证据并完成处置；成功标准是异常状态与下一动作可确认。产品规则和权限来自已确认 PRD，非目标是不改变对账规则和审批权限。

## 信息架构与关键路径

信息架构按待处理、处理中、待复核和已关闭分组。关键路径为异常列表 -> 查看证据 -> 选择处置动作 -> 提交复核 -> 查看结果；页面层级、筛选条件和返回位置保持稳定。

## 状态矩阵与失败恢复

覆盖 default、hover、focus、selected、disabled、loading、empty、partial、error、timeout、retry、read-only 和 unauthorized。提交失败保留用户输入并回到错误字段；超时允许查询处理结果，避免重复提交。

## 响应式与可访问性

桌面端保留表格比较，窄屏改为按异常展开的摘要列表。所有功能支持键盘，焦点顺序、可见焦点、可访问名称、状态通知、200% 缩放、CJK 长文本和触控目标进入验证。

## 视觉系统约束

继承现有 tokens、组件和图标。颜色不作为唯一状态通道；任务型界面保持高信息密度，不使用营销式 hero、装饰卡片或无依据的新视觉体系。

## 验证证据与停止条件

验证桌面与移动关键路径、键盘与焦点、错误恢复、长文本、大数、权限失败和弱网。没有真实浏览器走查、关键内容范围或产品 owner 确认时，只能交付设计级结论，不宣称生产可用。
