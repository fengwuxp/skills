# 异常工作台任务型可用性验证计划

## 研究问题与范围

验证问题是财务运营能否在不求助的情况下定位对账差异、补充证据并提交复核。范围覆盖桌面 Web 的异常列表与详情侧区，不改变业务规则；假设是证据与动作处于同一上下文能减少往返和误判。

## 目标用户与任务

参与者为每周处理异常的财务运营人员，招募时覆盖新手与熟练用户并排除本功能设计者。任务从收到一条差异告警开始，成功标准是选对异常、找到关键证据、提交正确处置并确认结果；失败包括误选对象、重复提交、无法恢复或需要主持人代办。

## 方法与执行

先用实现后的测试环境做认知走查，再进行五名目标用户的一对一任务测试。主持人只读任务背景，不提示控件位置；记录屏幕、操作路径和口述反馈。统一浏览器、权限与样本数据，测试前取得记录同意并隐藏真实客户数据。

## 证据与判断

逐人记录任务是否完成、错误与恢复、求助次数、用时和完成后信心，并保留触发步骤与原话。用时只用于定位阻塞，不做跨人排名；小样本观察不外推为总体比例。finding 的严重度由任务阻断、发生条件和恢复成本共同判断。

## 复测与停止条件

P0/P1 finding 修复后用同一任务和起点复测，同时执行桌面与窄屏 Design QA、键盘焦点和错误恢复检查。Owner 为 UI 设计与前端负责人；没有目标用户、可运行实现或可复核记录时停止宣称“已验证可用”，只保留设计级结论和残余风险。
