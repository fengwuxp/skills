# Web 审批流程契约计划

## 目标、层级与边界

目标用户是审批运营，验证问题是页面与状态定义能否关闭实现分叉。选择 L0 流程契约；范围覆盖待办、详情、退回和结果，非目标是不创建画布或代码。当前假设单人审批，产品 owner 负责确认规则。

## 页面、状态与真实内容

入口为待办列表，退出为结果页，重置回到同一条待办。页面图与状态图覆盖 default、loading、empty、error、success、权限不足和弱网，并使用脱敏但真实长度的数据说明溢出。

## 交互与失败恢复

交互表逐项记录 source、trigger、condition、action、destination、feedback 和 failure。退回失败时保留用户输入并把焦点移到错误摘要；取消后返回详情。

## 工程交接与可访问性

响应式契约覆盖桌面与移动，说明键盘、焦点、可访问名称、对比和 200% 缩放要求。工程只接收页面图、状态图、交互表和待确认项，本轮不生成实现。

## 验证证据与停止条件

由产品 Owner 确认页面图、状态图和交互表，并做一次成功、失败与返回的任务走查；保存版本和验证证据。L0 不证明可点击、不证明可访问、不证明可实现；规则未确认时停止并记录残余风险。
