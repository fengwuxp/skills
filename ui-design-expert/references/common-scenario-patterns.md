# 常见 Web UI 场景模式

## 使用时机

当任务属于高频业务界面，需要快速确定结构、关键状态、响应式变化和可用性检查时读取。本文件提供问题模式，不是页面模板。

## 不适用场景

- 产品对象、规则、权限或成功口径尚未确认。
- 只因页面名称相同就复制固定布局。
- 沉浸式游戏、原生移动应用或已有设计的工程还原。

## 读取后必须产出

- 命中的场景、主任务和不适用的模式。
- 页面结构、主行动、状态与失败恢复。
- 移动端、键盘、焦点、长内容和真实数据的验证点。

## 一、数据工作台与表格

- **主任务**：扫描异常、比较对象、批量处理、下钻证据并返回原上下文。
- **结构**：稳定标题与范围 -> 摘要/异常入口 -> 筛选与已用条件 -> 数据表 -> 批量/行级动作 -> 详情或证据侧区。
- **状态**：加载骨架不改列宽；空数据区分“确实无数据”和“筛选无结果”；部分、过期、权限不足和导出处理中可见。
- **响应式**：优先保留对象、状态和主动作；复杂表格可改为优先字段列表或横向滚动，不把每个单元格变成卡片。
- **检查**：表头语义、排序状态、行选择名称、批量动作范围、键盘操作、固定列遮挡、大数和长值。

## 二、搜索、筛选与结果

- **主任务**：表达查找意图、理解当前范围、调整条件并判断结果质量。
- **结构**：搜索输入 -> 常用条件 -> 已选条件 -> 结果摘要 -> 排序/视图 -> 结果；高级条件只在有真实需要时渐进披露。
- **状态**：初始推荐、输入中、查询中、无匹配、部分结果、错误、超时和条件无权限不能混成一个空态。
- **恢复**：保留查询和筛选；提供清除单项、全部重置、重试和返回上一结果的路径；需要分享时同步到 URL。
- **检查**：输入标签、自动完成键盘行为、结果计数、筛选冲突、拼写与 CJK 分词边界由真实搜索能力决定。

## 三、表单与分步任务

- **主任务**：以最少认知负担提交正确数据，并能发现、修正和恢复错误。
- **结构**：相关字段分组；字段少且可一次理解时保持单页，只有依赖、风险或保存边界明确时才拆步骤。
- **状态**：未编辑、编辑中、本地校验、服务端校验、上传中、保存草稿、提交中、失败、成功和过期。
- **恢复**：错误贴近字段并给下一步；摘要链接回具体字段；返回修改保留输入；重复提交、离开未保存和弱网有明确处理。
- **检查**：可见标签、必填含义、自动填充、输入模式、软键盘、焦点移动、错误通知、200% 缩放和超长选项。

## 四、审批与复核

- **主任务**：看清请求、证据、风险、历史和决定后果，再作可审计决策。
- **结构**：对象与当前状态 -> 关键差异/风险 -> 证据 -> 历史 -> 决策区；证据与动作在同一工作上下文内可对照。
- **状态**：待处理、已认领、并发更新、证据缺失、需补充、批准、拒绝、撤回、过期和只读。
- **风险**：批准与拒绝不可只靠颜色区分；高后果动作说明范围和后果，必要时确认或二次授权；不以默认选中替用户作决定。
- **检查**：操作者身份、决定理由、版本冲突、审计时间、返回队列位置和键盘完成主路径。

## 五、设置、权限与配置

- **主任务**：理解当前值、影响范围和生效时机，安全地修改或恢复。
- **结构**：按用户心智而非代码模块分组；当前值、继承来源、可编辑范围和生效影响靠近控件。
- **状态**：默认、已修改、保存中、保存失败、部分成功、无权限、由上级策略锁定和等待生效。
- **风险**：切换开关只用于立即改变单一二元状态；复杂或高风险配置使用明确保存、影响预览和回退。
- **检查**：脏状态、离开提示、继承冲突、权限差异、敏感值遮罩、审计与回滚路径。

## 六、监控与仪表盘

- **主任务**：回答“发生了什么、是否需要行动、影响多大、去哪里处理”，而不是展示尽可能多的图。
- **结构**：范围与新鲜度 -> 关键状态 -> 异常/趋势 -> 影响对象 -> 行动入口；指标定义和时间范围可追溯。
- **状态**：正常、告警、无数据、延迟、部分数据、采集中断、阈值变更和权限不足。
- **视觉**：颜色之外使用标签、形状和文本；同图只保留可比较序列；避免 3D、双轴和无法解释的装饰仪表。
- **检查**：时间区间、时区、刷新、数据新鲜度、阈值来源、异常下钻、屏幕缩放和非视觉替代。

## 七、任务型服务与恢复

- **主任务**：从用户真实需求到可确认结果设计完整服务，不以某个页面上线代替任务完成。
- **结构**：只在任务需要时组合开始页、逐步提问、答案核对、确认页和后续指引；不要机械地一页一字段，也不要提前要求系统已经掌握的信息。
- **错误恢复**：错误文案对应具体问题，说明发生了什么和下一步；错误摘要把焦点带回字段并保留已输入内容。
- **确认页**：明确结果、参考编号或记录状态、接下来会发生什么，以及用户仍需完成的动作；不能只显示笼统“成功”。
- **服务不可用**：说明受影响范围、已提交数据是否保留、何时重试、替代渠道和返回路径；无法确认时不得伪造成功或恢复承诺。
- **证据**：页面拆分、内容顺序和恢复路径来自用户需求、数据与任务测试；高后果场景明确业务 Owner 和支持责任。

## 组合与停止

- 一个页面可组合多个模式，但必须只有一个当前主任务；不要把工作台、设置、审批和仪表盘堆成同权首页。
- 项目已有成熟模式时继承其结构与行为，只修证据明确的问题。
- 模式不能回答业务对象、权限或规则时停止设计，交回产品 Owner；不能证明实现状态时停止宣称可用。
