# 对象与完成层级

读取时机：需要建模支付/转账/发卡资金链、解释重试或判断“成功”证据时读取。这里描述跨厂商语义，不定义厂商对象或状态。

## 对象矩阵

| 层 | 记录内容 | 不可替代为 |
| --- | --- | --- |
| 业务意图 | 用户或业务要达成的收款、付款、转账目标及业务幂等标识 | 一次 API 调用 |
| 尝试语义 | 针对意图的认证、授权、路由或重试历史 | 必然存在的厂商 Attempt 对象 |
| 交易/资金事实 | 已观察的授权、捕获、清算、入账或外部转移 | 业务意图或通知名称 |
| 退款/争议 | 关联原交易但独立的逆向资金路径 | 覆盖原交易状态 |
| 财务事件/账务 | 本金、费用、汇差、临时贷记和账本影响 | 结算批次或余额快照 |
| 结算 | 批次、外部网络或银行的清分结算事实 | 余额可用或业务履约 |
| 余额 | 特定 owner、账户、币种、时点的可用/待处理余额 | 全生命周期结果 |

每行至少记录：本层 ID、关联 ID、owner、币种/金额、时间语义、当前证据来源、版本和状态的权威来源。保留失败与重试历史；没有显式 attempt 对象时，写“尝试语义未映射”而不是创建假对象。

## 分层完成证据

分别为业务、通道、账务、结算、余额写 `provisional`、`final`、`failed` 或 `unknown` 及其证据。只有满足该问题所需层级的 `final` 才能作出最终承诺。

- API 或事件成功但没有更深层证据：保持 `provisional`。
- 超时或处理中：以原幂等语义、原对象关联和权威查询恢复，不重复创建资金请求。
- 迟到失败、退票、退款、争议或撤销：追加独立财务事实，重新计算净额与承诺。
- 证据冲突：保留冲突，不以较早事件回退当前投影，转入权威查询、报告或人工调查。

厂商精确对象、字段、状态、留存期和版本只在 [厂商时效事实](provider-facts.md) 中使用，并在目标环境复核。
