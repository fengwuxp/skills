# 工程项目 AGENTS.md 模板

## 使用时机

用户要求初始化、重构或完善工程项目的 `AGENTS.md` 时读取。本文适用于不同语言的项目工程约定；Java/Wind 专项由 `wind-coding-conventions` 提供。普通编码不因本模板存在而创建或重写项目规则。

## 取舍与归位

- 项目文件承载当前项目的稳定事实、工程边界和可执行验证入口；全局行动基线、专业 Skill 的详细知识与本轮任务记录分别保留在各自位置。已有上位规则覆盖的内容不重复粘贴。
- 兼容是对真实消费者和数据的责任，不是无限保留旧实现。先核对已确认的兼容要求；明确无需兼容且删除范围获准后，移除旧路径及其专属残留。仍有消费者或持久数据时，按实际契约完成必要迁移和恢复，不用“个人项目”推定可以丢弃。
- 最小实现须完整承担当前需求；可演进不等于预建平台。新增能力按可验收的纵向切片交付，保留现有可用功能。必要过渡有责任、验证和退出条件；不能用长期设计拒绝有依据的过渡，也不能把临时绕过包装成最终方案。
- 借鉴先看项目现有实现、依赖文档、类型与测试；真实设计分叉需要外部经验时再研究成熟产品，比较目标、规模、依赖和失败边界。原模式在别处成功不证明适合本项目，也不为普通小修强制联网调研。

## 生成与改进

1. 读取目标项目已有根目录及局部指令、模块入口、构建与 CI、实际依赖、相关消费者和测试。优先更新已有文件，只补影响 Agent 判断的缺口。
2. 下面是可裁剪的起点；按事实填充项目项，删除不适用章节、示例和已被上位规则覆盖的条款。能从源码确认的内容自行确认；关键未知标明具体缺口，只暂停依赖它的动作，不交付带猜测命令的“可直接执行”规则。
3. Java 项目从 Java 约规提取实际适用差量；只有命中 Wind 高置信度信号时，才合并其 `wind-project-agents-template.md` 的专项内容。通用模板不默认加入 face/impl、Spring 或 Wind 类型。
4. 交付前核对项目事实、指令作用域、引用可达性、命令与验证范围；已有命令要确认入口与用途，未实际运行的命令不声称验证通过。模板只授予规则，不能授予 Git、部署、生产或删除权限。

## 模板正文

下列占位符供生成时定位事实，不是应原样写入真实项目的内容。

```markdown
# AGENTS.md

## 项目与边界

- 项目用途：<当前产品提供的真实能力及主要使用者>。
- 关键入口与模块：<入口路径、职责归属、允许依赖方向和需要保护的不变量>。
- 项目权威：<现行架构/接口/数据约定的实际路径；只列影响当前工程工作的来源>。

## 工程原则

1. 改动接口、数据结构或可观察行为前，核对真实消费者与兼容要求。明确不需兼容且移除范围获准后删除旧路径，不另造无用途的兼容层；仍有兼容义务时保留必要迁移、验证与恢复安排。
2. 选择完整满足当前需求的最简单实现。先复用现有能力，不为未出现的需求增加抽象、配置或间接层；必要的权限、数据不变量、失败处理和测试不能省略。
3. 新能力先完成可端到端验证的最小切片，再在可用结果上演进；不为未完成的复杂设计拆掉现有功能，不以空壳、模拟入口或测试替身冒充生产能力。
4. 按稳定职责、数据责任和真实变化轴组织模块；有边界价值时依赖稳定接口，通过组合协作。既不把所有逻辑塞入一处，也不为每个类机械配接口或透传层。
5. 写新实现或加依赖前，先核对项目已有库的实际版本、文档、类型和现成能力。确有缺口时，再比较成熟且维护良好的库与自研的总成本、可靠性和适配性，不重复实现已经可用的常见功能。
6. 架构选择考虑持续维护与退出成本，不以明知很快推倒的绕过方案交差；确需阶段过渡时明确责任、验证和退出条件，保护当前可用性，不为想象中的长远目标过度设计。
7. 有真实设计分叉时，先从既有实现和成熟产品中找可借鉴做法，核对适用条件后采用；简单局部变更不强制调研报告，外部资料不足时保留未知，不虚构已验证的最佳实践。
8. 代码首先服务阅读与维护。命名、结构和控制流应让人看清意图、边界和失败路径；保持项目已确认的风格，只修改当前任务必要范围。

## 项目验证

- 工具链与运行目录：<会影响执行的版本、模块目录和项目指定环境>。
- 构建或类型检查：<已核对的命令、适用模块和用途>。
- 目标测试：<相关行为、失败边界与对应命令>。
- 格式与静态检查：<项目实际选用的配置和命令>。
- 按改动风险运行必要检查，核对实际执行、失败和跳过项；文档变更只跑适用检查。验证通过后不无故重复或扩大范围。

## 项目特例

<只保留本项目确有依据的兼容承诺、迁移/删除限制、环境与敏感数据边界；没有特例则删除本节。授权仍以当前用户和上位规则为准。>
```

## 维护边界

模板中的通用工程判断在本文维护，语言与框架差量归对应规则 Skill。生成到消费项目后，该项目按自身事实维护实际规则，不因源模板更新自动覆盖。新发现应修正真正的责任或执行缺口，不向每个项目追加长清单、固定审批或未知的验证命令。
