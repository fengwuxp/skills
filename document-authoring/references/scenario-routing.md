# 文档场景路由

## 使用时机

在开始正式文档任务前读取，用于判断本技能是否为正文 owner、只负责载体，还是应停止并路由专项 Skill。

| 用户任务 | 主责 | 本技能职责 | 停止条件 |
| --- | --- | --- | --- |
| 报告、制度、手册、研究说明、总结 | `document-authoring` | 从材料到正式文档闭环 | 目标读者、来源或验收方缺失 |
| 专业培训材料、课程讲义、讲师手册、桌面推演与情景演练手册 | `document-authoring` 持有文档与训练结构，领域事实 owner 持有专业结论 | 组织学习路径、案例、练习、事件卡、讲师提示、答案边界和载体 | 训练后的可观察行为、领域事实来源、训练环境或验收方缺失 |
| 公文、法律或合规文件 | 对应内容 owner 与法律 / 合规专业方 | 只按已批准、当前有效的权威模板处理结构和载体 | 法域、效力、签批链或权威模板未确认 |
| PRD、产品方案、需求说明 | `产品架构专家` | 可在产品结论稳定后做载体和表达检查 | 产品对象、规则或验收未确认 |
| 系分、ADR、技术方案 | `资深架构师` | 可在工程结论稳定后做载体和表达检查 | 接口、数据、风险或验证未确认 |
| 字源、训诂、古文字研究 | `hanzi-philology` | 消费训诂证据卡并形成正式文档 | 来源、时代或争议状态不清 |
| 作者侧正典档案、编辑梗概、读者附录、设定集、人物档案、时间线、决策台账 | `novelist` 持有故事语义，`document-authoring` 持有文档工程 | 统一权威、职责、状态、引用、版本和载体，并按阅读进度与剧透等级过滤信息 | 作者权威、设定状态、受众侧或允许写回范围不清 |
| 小说总纲、卷纲、章卡、叙事语体或正文创作 | `novelist` | 仅在故事结论稳定后处理正式载体 | 不得以文档整理替代叙事判断和连续性审查 |
| DOCX/PDF/PPTX/表格编辑 | 环境可用的文档工具 | 提供内容契约和最终语义检查 | 工具不可用或无法渲染验证 |
| 简单润色、翻译、格式微调 | 当前 Agent | 直接完成最小修改 | 任务扩大为完整正式文档 |

复合任务先由领域 Skill 产出稳定事实，再由本技能在同一权威版本上组织正文，最后由载体工具生成和渲染文件。培训材料不得反向创造领域事实；情景演练只压当前定义的能力目标，不把练习表现外推为人员绩效或岗位等级。载体转换不得改变领域结论；PRD、系分和小说设定集等领域文档编辑完成后重新运行领域 Skill 的交付物检查，只对实际派生载体执行渲染检查，不套用本技能的报告、制度、手册或研究说明结构检查器。用户指定机构、出版方或平台格式时，必须读取其已批准且当前有效的模板；没有一手模板时只给通用结构，不推定专有格式。
