# 写作与结构

## 使用时机

文档契约已明确，需要组织正文或重构既有文档时读取。

先按文种与效力、读者关系和阅读后动作选择结构，不把所有文档统一为“结论先行”。标题表达对象和用途，不用营销词替代主题。

## 中文场景路由

| 场景 | 结构与语体 | 红线 |
| --- | --- | --- |
| 管理汇报、决策报告 | 关键事实、风险状态、决策请求、方案取舍、行动责任优先 | 不把样本外推为全量事实，不埋没需要批准的事项 |
| 调研、研究、论证 | 先界定问题、范围、方法、统计口径与局限，再写事实、推断、异议和阶段结论 | 不为“有结论”伪造因果或消除反证 |
| 制度、办法、规范、细则 | 用明确主体和“必须 / 不得 / 应 / 可以 / 建议”表达效力，组织为范围、定义、职责、规则、流程、例外、记录和复审 | 不用宣传语替代可执行规则，不混淆强制与建议 |
| 手册、SOP、Runbook | 按前置条件、动作、预期结果、验证、失败处理和停止条件组织 | 不省略异常路径，不把背景说明写成操作步骤 |
| 会议纪要、决议、Decision Log | 分开事实、分歧、决议、行动、owner、期限和待确认项 | 不把发言写成决议，不静默消除异议 |
| 总结、复盘、事故报告 | 目标与结果、事实时间线、偏差机制、影响、行动与复验相互回链 | 不写甩锅叙事，不用空泛心得替代证据 |
| 对外方案、白皮书 | 先建立对象、问题和价值，再给依据、方案、边界、案例、风险与下一步 | 不虚构背书、数据、客户案例或对外承诺 |
| 公文、法律或合规文件 | 只按适用主体批准且当前有效的模板、法域、签批与用语要求成文 | 未有权威模板或专业确认时不得自行推定格式与效力 |

## 专业培训与情景演练

专业培训先定义训练后的可观察行为，再选择内容、案例和题型。领域事实由对应专业 Skill 或 Owner 提供；本技能只把稳定结论组织成可学习、可练习、可复核的训练材料。

训练契约至少确认：目标读者与角色、前置知识、学习后要完成的真实任务、已稳定事实源、训练环境、允许使用的工具、验收证据、领域事实 owner、训练验收方和停止条件。推荐按风险裁剪渐进路径：

```text
阅读/诊断 -> 桌面推演 -> sandbox/仿真 -> 历史案例 -> 受控真实任务
```

不是每个主题都必须走完五级；只有前一级证据足够、环境和授权允许时才升级。能复述概念只证明材料可理解，不证明能在异常和信息不全时执行；不把摘要加选择题当成能力训练。

场景包默认使用虚构或脱敏数据，角色私有信息按角色与任务最小披露；领域结论使用权威指针或经 Owner 确认的脱敏最小结论，不逐条粘贴未脱敏原始材料。学员版不携带角色外信息、讲师提示和参考答案，讲师版也不得暴露不必要的真实客户、交易、事故或生产信息，并分别设置载体或访问边界。sandbox、历史案例和受控真实任务必须分开标识；未获明确授权不得触发真实资金、生产写入、密钥操作或不可逆动作，受控真实任务还要保留环境 owner、人工接管和停止条件。

情景演练至少包含：

- 目标、角色、前置事实、角色私有信息、未知项、对象与初始状态。
- 一次只压一个主能力的事件卡；写明触发时机、新增事实、允许动作和不可撤销影响。
- 交付物、红线、停止条件、检查点，以及由谁观察、确认或裁决。
- 讲师提示：何时发事件、观察哪些行为、何时追问、何时停止或转人工。
- 参考答案：给判断依据、事实/推断/待确认、关键证据和可接受分支，不把固定措辞或唯一流程当成唯一正确答案。

培训准出需要同时满足三层证据：文档结构与载体可用、领域 owner 确认事实未被改写、目标学习者在约定场景中产出可复核行为。静态检查、讲师自述和高分问卷不能单独证明能力形成。

上行材料压缩过程、突出判断与请求；平行协作材料明确接口、依赖与分歧；下行执行材料明确主体、条件、动作和验证；外部材料只写已经获准公开和承诺的内容。中文行文保持一事一名、一句一个主判断、责任主体可见，统一编号、日期、数字、单位与标点；删除空话、整齐排比和无信息口号，不把所有文档统一成同一种机关腔。

## 小说与创作项目

| 产物 | 主责与写法 | 信息边界 |
| --- | --- | --- |
| 小说正文、样章 | `novelist` 主责，以场景、人物声音、动作、节奏和言外之意推进 | 不套报告结构，不替人物总结主题 |
| 故事总纲、卷纲、章卡 | `novelist` 主责，记录目标、阻力、选择、变化、代价与后续接口 | 候选不自动成为正典 |
| 作者侧正典档案 | 编号记录已确认事实、适用范围、连续性约束和待决定项 | 可完整剧透，区分作者本真与人物所知 |
| 读者附录 | 按目标读者的阅读进度、语境和阅读目的组织 | 只呈现读者所知，不泄露伏笔性质和后续揭晓 |
| 出版编辑用梗概 | 用连续叙述交代主角、主冲突、关键转折、结局与作品价值 | 可完整剧透；材料不足时列缺口并停止，不补造剧情 |
| 时间线、连续性与伏笔/承诺台账 | 用稳定字段记录事件、状态、依赖、首次出现、强化、回收窗口和实际回收 | 不替正文回收伏笔，不把弱细节强行赋义 |

## 通用结构判断

1. 一个章节只回答一个核心问题；标题应让读者不读正文也能理解结构。
2. 事实与判断相邻，但必须用来源、措辞或栏目清楚区分。
3. 表格只用于重复字段比较；连续论证、取舍和因果关系使用正文。
4. 删除不承载事实、判断或行动的套话；不为“完整”复制不适用章节。
5. 正式设计文档先服务人的理解：背景、目标、定性、方案、流程、规则和接口抽象构成正文；追踪矩阵、测试映射、命令、owner 和任务状态等执行控制放在末尾附录或独立执行计划。

报告型文档的默认顺序可按需要裁剪：结论摘要、背景与范围、事实与证据、分析与取舍、结论与行动、风险与待确认、附录与引用。研究、制度、操作和创作产物按上表选择自己的开头与推进方式。
