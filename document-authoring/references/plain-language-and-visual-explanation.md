# 通俗视觉讲解

## 使用时机

当已稳定的领域事实需要整理为面向明确受众的一页说明、视觉预习页、零基础 onboarding 或概念图解时读取。普通两三句话解释直接完成；专业事实尚未稳定、需要完整课程训练、操作手册或产品界面时，分别回到领域 owner、专业培训、手册或 UI 路径。

## 目标与边界

通俗讲解不是把内容写给抽象的“五岁小孩”，而是帮助特定读者在特定情境下回答一个问题或完成一个动作，同时保留决定结论的条件、例外和不确定性。

本文把《礼记·学记》的因人救失、约而能达、引导思考，《周易·系辞》的以象辅言，以及现代 plain language、多媒体学习、类比与无障碍研究转成当代文档方法。这是现代综合，不是经典原文的唯一解释；经典只校准取舍，不证明现代页面有效。

## 讲解契约

开始前确认：

```text
目标受众与前置知识：
当前要解决的一个问题：
阅读后应能完成的动作：
领域事实 owner 与事实源：
必须保留的条件、例外和未知：
最容易发生的误解：
目标载体与验收方：
```

缺少受众、核心问题或稳定事实源时停止扩写。缺少目标载体不妨碍先形成内容结构，但不得宣称 HTML、图片、响应式或可访问性已经完成。

## 定人、正名、取象、节文、启验

这五步是本项目的现代方法名，不冒充古代固定术语或教学体系。

### 定人

- 以读者的真实任务、前置知识、常用语言和已知误解确定解释深度。
- 不用年龄、学历、职位或“外行”替代事实调查；同一主题面对采购、开发、管理者和公众时，例子与边界可以不同。
- 将“看懂”改成可观察结果，例如能复述核心关系、识别适用条件或完成一个近迁移判断。

### 正名

- 先用一句可核验陈述说明对象是什么、解决什么问题、不是什么。
- 把事实、推断、未知和范围外内容分开；术语由领域 owner 确认，文档能力不补造专业定义。
- 简化表达不得删除会改变结论的主体、条件、例外、时间、数量、风险或责任。

### 取象

只有图像、图表、流程、状态或类比能比正文更清楚地表达关系、过程、尺度、变化或差异时才使用。装饰图、背景图和大号 emoji 不计作视觉解释。

类比至少写清：

```text
目标概念中的关系：
类比对象中的对应关系：
能够帮助理解的部分：
不再成立的失效点：
```

类比只辅助理解，不替代定义和来源。表面相似但因果、主体能力、责任或边界不同的类比应舍弃；找不到可靠映射时，改用过程图、对照表、真实示例或直接说明。

### 节文

- 一个信息区块只承担一个主判断，先给核心关系，再按需要展开原因、过程、条件与例外。
- 删除无关装饰和重复，不删除理解所需的事实；一页容纳不下时，把一页定义为入口层，并提供深入来源。
- 使用标题、编号、位置和克制强调提示结构；对应图文放在相邻位置，避免让读者在远处分散匹配。
- 留白用于形成层次和阅读节奏，不用空白掩盖信息缺口；不默认套用卡片墙、水墨、红金、书法或仿古样式。

### 启验

核心事实必须明说；可以通过问题保留需要读者自己连接的关系，不以故作含蓄代替解释。

至少选择一种验证：

- **复述测试**：目标读者不用照抄原文，以自己的话说出核心关系和一个边界。
- **近迁移测试**：给出结构相近的新情境，让读者判断概念是否适用并说明理由。
- **任务测试**：涉及查找或操作时，观察读者能否找到信息并完成约定动作。

一次回答正确只证明当前最小问题可能被理解，不证明长期掌握、专业胜任或真实业务能力。

## 页面与视觉结构

按内容裁剪，默认顺序为：

```text
主题与一句正名
-> 一个主关系图、过程图或关键对照
-> 少量渐进信息区块
-> 类比映射与失效边界（确有类比时）
-> 复述、近迁移或任务验证
-> 来源与继续深入入口
```

- 视觉表达必须回指正文事实，不根据版面需要新增数据、因果、角色或结论。
- 颜色、位置、形状、图标或动效不得成为唯一信息通道；信息图和复杂图像提供等价文字或可访问描述。
- 正文在图像不可见时仍能成立；图片中的关键文字不得只存在于位图中。
- HTML 或其它浏览器载体还要检查语义结构、键盘与焦点、对比、缩放、文本回流、目标视口和减弱动效。
- 对话内需要实际图解且环境提供 `visualize` 时，可由其生成视觉产物；独立网页的界面设计由 `ui-design-expert` 主责，工程实现与运行验证交给工程能力。工具不替代本 reference 的内容契约。

## 分支与停止

| 情形 | 处理 |
| --- | --- |
| 事实仍有争议或来源失效 | 停止成稿，交还领域 owner；只列已知、冲突和待确认 |
| 一页会删掉关键条件 | 将一页降为入口层，保留深入链接，不强行压缩 |
| 类比只能制造表面相似 | 舍弃类比，改用关系图、过程图、对照或直接解释 |
| 用户只要简短口头解释 | 当前 Agent 直接回答，不启动完整文档流程 |
| 需要完整课程、练习或能力训练 | 回到 `writing-and-structure.md` 的专业培训路径 |
| 需要 SOP、决策、PRD、系分或法律结论 | 路由对应 owner，不用通俗页替代正式契约 |

## 准出证据

通俗视觉讲解至少分开检查：

1. **事实保真**：领域 owner 确认定义、关系、条件、例外和来源未被改写。
2. **读者理解**：目标读者完成约定的复述、近迁移或任务测试；作者自述“很清楚”不算证据。
3. **视觉语义**：每个视觉元素确实表达正文关系；装饰不进入理解链。
4. **载体可用**：实际生成的 Markdown、HTML、图片、DOCX、PDF 或 PPTX 按载体检查；没有真实产物时不得声明渲染、响应式或可访问性通过。

静态 fixture、结构检查和模型评分只证明契约或格式可检查，不证明目标读者已经理解。
