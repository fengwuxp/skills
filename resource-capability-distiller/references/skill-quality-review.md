# Skill 质量评审

## 使用时机

资源提炼任务涉及外部 Skill 示例或能力候选归位时读取。本源仓库的普通 Skill CR 也可由 `AGENTS.md` 直接引用此方法，仍按 `skill-creator` 维护，不触发完整提炼流程。本 reference 不接管领域事实、运行效果或安装准入。

## 五项标准

| 项目 | 核对内容 |
| --- | --- |
| Description | 是否说清能力、触发场景和用户关键词，能区分相邻能力；不塞入长步骤、口吻或营销承诺。 |
| 调用策略 | 对照 `agents/openai.yaml` 的 `allow_implicit_invocation`、描述、显式调用约定、fixture 和 admission。保留现有策略，不能仅因高风险或候选身份擅改；策略一致不等于真实触发通过。 |
| 入口路由 | `SKILL.md` 是否说清动作、必要读取顺序、交付与停止条件；保留失败分支、未知和候选边界，专题细节按需读取，不用固定流程排除合法路径。 |
| 按需资源 | 专题、模板、工具 schema 和案例是否归入 reference / script / asset / fixture，有一层直连指针；较大或多任务 reference 提供使用边界和任务索引，同一规则只有一个权威位置。 |
| 行为一致性 | 对账正文、metadata、admission、references、脚本、fixture 与实际产物；涉及交付时再查安装副本。声称的能力、文件和结果是否真实可用，是否把结构检查当成了行为证明。 |

## 评审顺序

1. 读取当前资产与用例；借鉴外部示例时另读其实际源码，分开可迁移方法、示例特例和未证明效果。
2. 每项发现给出来源、触发条件、影响、最小修复及验证；区分缺能力、缺证据和不应修改。先修共享根因，再考虑拆分，已满足要求的资产不为统一形式重写。
3. 静态验证检查结构，实际运行正反例检查触发和输出。没有重复对照、独立评判或真实产物支撑时，只报告已观察的变化，不以 fixture、官方身份或静态分数声称能力提升。

## 输出契约

按任务给出 Skill 与版本、五项结论、发现及最小变更、验证和残余边界；没有缺口可直接说明，不强填模板。

行数、段落数、是否全部使用祈使句、是否拥有同样数量的 reference 都是观察项，不是单独的失败条件。简单 Skill 可以没有 reference；复杂 Skill 可以较长，但必须能按任务定位并保持入口不吞并专题细节。
